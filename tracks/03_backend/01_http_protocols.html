Modul 10: Protokol Komunikasi: Anatomi HTTP/TCP & Real-Time Web

Membedah fondasi transmisi data internet: anatomi paket HTTP/1.1 plain text, multiplexing binary frame HTTP/2, revolusi HTTP/3 berbasis QUIC (UDP 0-RTT handshake), serta pemilihan protokol real-time yang presisi antara Polling, Server-Sent Events (SSE), dan WebSockets.

Fondasi Konsep: Protokol Jaringan HTTP/1.1 hingga HTTP/3
Ibarat Jalan Tol Pengiriman Surat Dunia
Apa Ini Sebenarnya?

HTTP adalah bahasa kesepakatan internasional agar komputer pembeli di rumah bisa memesan dan menerima halaman web dari komputer server di belahan bumi lain.

Masalah Nyata Apa yang Diselesaikan?

Tanpa protokol standar, komputer Apple tidak akan bisa mengerti data yang dikirim oleh server Linux, dan internet global tidak akan pernah bisa bekerja.

Analogi Kehidupan Sehari-Hari

Ibarat jalan tol pengiriman surat: HTTP/1.1 adalah jalanan 1 lajur sempit (antre macet), HTTP/2 membuat jalan tol 8 lajur paralel, dan HTTP/3 adalah drone terbang kilat anti macet.

Kapan Kita Memakainya?

Dipahami saat merancang komunikasi API kilat, optimasi video streaming, dan koneksi internet di daerah bersinyal lemah.

1. Lapisan Transport & Aplikasi Jaringan Web

Setiap byte data yang Anda kirimkan dari backend ke browser diatur oleh tumpukan protokol internet. Selama lebih dari 25 tahun, web bertumpu pada TCP (Transmission Control Protocol) untuk menjamin keandalan pengiriman data tanpa paket hilang. Namun seiring meningkatnya tuntutan kecepatan dan latensi mobile, arsitektur lama menghadapi dinding batas fisik.

3. Masalah Head-of-Line (HoL) Blocking

Untuk memahami mengapa HTTP/3 diciptakan, kita harus memahami apa itu Head-of-Line (HoL) Blocking:

Analogi Antrean Truk di Terowongan Sempit
Pada HTTP/1.1: Bayangkan terowongan satu lajur. Truk pertama (gambar hero 2MB) berjalan sangat lambat. Truk kedua (file CSS kecil 5KB) terperangkap di belakang truk pertama dan tidak bisa mendahului. Seluruh halaman terblokir menunggu request pertama selesai.

Pada HTTP/2: HTTP/2 memecah muatan truk menjadi paket-paket kecil (frames) bernomor ID, sehingga file CSS bisa diselipkan di sela-sela paket gambar (Multiplexing). Namun ada masalah baru: Karena di bawahnya tetap menggunakan TCP, jika satu paket saja hilang di jaringan (packet loss 1%), kernel OS akan menghentikan SELURUH multiplexing stream sampai paket yang hilang tersebut dikirim ulang! Inilah TCP-level HoL Blocking.

4. Bedah QUIC: UDP, Enkripsi TLS 1.3 & 0-RTT Connection

Google dan IETF memecahkan masalah TCP-level HoL blocking dengan merancang protokol baru: QUIC di atas UDP (User Datagram Protocol).

1. Stream Independence
Pada QUIC, setiap stream HTTP/3 berdiri sendiri. Jika paket data untuk Request A hilang di jalan, Request B, C, dan D tetap terus berjalan normal ke browser tanpa tertahan sama sekali!
2. Connection Migration
Koneksi TCP diidentifikasi oleh 4 tuple: (IP Sumber, Port Sumber, IP Tujuan, Port Tujuan). Jika user keluar rumah dan HP beralih dari Wi-Fi ke 4G/5G, IP berubah dan koneksi TCP putus!
QUIC menggunakan Connection ID 64-bit acak: User dapat berpindah jaringan seketika tanpa memutuskan stream video atau download yang sedang berjalan!

6. Lab Hands-on: Membuat Real-Time Server-Sent Events (SSE) Server

Mari kita buat endpoint SSE sederhana menggunakan Node.js runtime untuk memahami betapa ringannya protokol streaming satu arah ini dibandingkan WebSocket:

server-sse.js (Node.js Native HTTP) 
const http = require('http');

http.createServer((req, res) => {
    if (req.url === '/events') {
        // 1. Wajib set Content-Type ke text/event-stream
        res.writeHead(200, {
            'Content-Type': 'text/event-stream',
            'Cache-Control': 'no-cache',
            'Connection': 'keep-alive',
            'Access-Control-Allow-Origin': '*'
        });

        // 2. Kirim stream event data berkala ke client:
        const timer = setInterval(() => {
            const data = JSON.stringify({ waktu: new Date().toISOString(), harga_btc: 95000 + Math.random() * 500 });
            res.write(`data: ${data}\n\n`); // Wajib diakhiri dua karakter newline
        }, 1000);

        req.on('close', () => clearInterval(timer));
    }
}).listen(3000, () => console.log('SSE Server berjalan di http://localhost:3000/events'));
Client Browser (1 Baris Kode Native!)
// Tanpa library tambahan! Browser otomatis me-reconnect jika koneksi terputus!
const evtSource = new EventSource('http://localhost:3000/events');

evtSource.onmessage = (e) => {
    const payload = JSON.parse(e.data);
    console.log('Update Data Masuk:', payload.harga_btc);
};

7. Production War Stories & Anti-Patterns

War Story: Salah Pilih WebSocket untuk Notifikasi 5 Juta Pengguna
Sebuah aplikasi berita online menggunakan WebSocket server untuk mengirimkan "Breaking News" kepada 5 juta pengguna ponsel.

Bencana yang Terjadi: Menahan 5 juta koneksi TCP socket terbuka aktif secara bersamaan memakan memori RAM server luar biasa besar dan mengharuskan pemeliharaan server stateful yang sangat rumit di belakang Load Balancer. Ketika jaringan mobile seluler pengguna fluktuatif di daerah terpencil, terjadi badai rekoneksi (*Thundering Herd*) yang merobohkan kluster server WebSocket.

Solusi: Menggantinya dengan Server-Sent Events (SSE) yang di-cache di Edge CDN (Cloudflare / CloudFront) atau Web Push Notifications. Server backend hanya mempublikasikan event satu kali, dan CDN yang mendistribusikannya ke jutaan pembaca secara stateless tanpa membebani server backend!

8. Kuis Uji Pemahaman: Protokol HTTP & Real-Time Web

1. Mengapa HTTP/3 menggunakan protokol QUIC di atas UDP alih-alih mempertahankan TCP seperti HTTP/2?
A. Karena UDP tidak memerlukan enkripsi keamanan sama sekali
B. Mengeliminasi TCP Head-of-Line Blocking sehingga paket yang hilang di satu stream tidak menghambat stream paralel lainnya
C. Karena TCP tidak bisa berjalan di jaringan kabel fiber optik
2. Untuk fitur streaming respon token teks dari LLM AI (seperti ChatGPT), teknologi mana yang paling ideal dan hemat sumber daya?
A. Short Polling setiap 100 milidetik
B. Server-Sent Events (SSE) karena aliran data bersifat satu arah (Server ke Client) di atas HTTP standar dengan dukungan reconnection otomatis
C. WebSockets dengan protokol binary gRPC
