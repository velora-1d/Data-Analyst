2. Taksonomi & Kamus Lengkap 35+ Komponen UI

Di industri teknologi profesional, sebuah aplikasi tidak hanya terdiri dari tombol dan input biasa. Berdasarkan standar desain global (*Apple Human Interface Guidelines, Google Material 3, Tailwind UI, Radix UI, Shopify Polaris*), komponen antarmuka diklasifikasikan ke dalam 5 domain fungsional besar:

Kategori 1: Navigasi & Orientasi (Wayfinding)

Komponen yang membantu pengguna mengetahui posisinya saat ini dan berpindah antar-layar tanpa tersesat.

Nama Komponen Definisi & Perilaku Antarmuka Kapan Wajib Digunakan?
Navbar / Top Navigation Pita menu horizontal di puncak halaman berisi logo brand, tautan utama, dan tombol profil. Navigasi tingkat paling atas (*root level*) pada aplikasi desktop dan tablet.
Sidebar Accordion Panel menu samping bertingkat yang dapat dibuka-tutup (*expand/collapse*). Dashboard aplikasi bisnis yang memiliki lebih dari 15 modul atau sub-menu.
Breadcrumbs Jejak remah roti horizontal penunjuk hierarki lokasi data (Home > Kategori > Sepatu). E-commerce atau dokumentasi teknis dengan kedalaman struktur lebih dari 2 lapis.
Tabs / Segmented Control Pengalih tampilan tab dalam satu kontainer tanpa memicu reload halaman web. Menampilkan data yang saling berkaitan (misal tab *'Deskripsi'*, *'Spesifikasi'*, *'Ulasan'*).
Pagination Kontrol pemecah daftar data per lembar (< 1 2 3 ... 10 >). Tabel database besar (misal 5.600 data transaksi) agar query backend ringan dan terukur.
Steppers / Wizard Indikator langkah berurutan (Langkah 1: Keranjang > 2: Alamat > 3: Pembayaran). Alur transaksi multi-fase yang membutuhkan data berurutan agar user tidak kewalahan.
Bottom Navigation Bar Menu tab 4-5 ikon yang menempel di bagian bawah layar smartphone. Navigasi utama aplikasi mobile agar mudah dijangkau ibu jari (*Natural Thumb Zone*).
Floating Action Button (FAB) Tombol bulat mengambang di pojok kanan-bawah layar. Aksi tunggal paling sering digunakan dalam satu layar (contoh: *'Tulis Pesan Baru'*, *'Buat Pesanan'*).

Kategori 2: Aksi & Pemicu Interaksi (Actions & Triggers)

Komponen yang dieksekusi pengguna untuk mengirimkan perintah atau mengubah kondisi sistem.

Tipe Tombol Karakter Visual Aturan Penggunaan Industri
Primary Button Solid warna brand (`#2563EB`) teks kontras tinggi putih. Hanya 1 per layar utama untuk aksi konversi paling krusial (*'Bayar Sekarang'*, *'Daftar'*).
Secondary Button Latar netral lembut (`var(--bg-surface-2)`) berbingkai tipis. Aksi pendukung penting yang tidak menyelesaikan alur (*'Simpan Draf'*, *'Lihat Preview'*).
Outline Button Transparan dengan garis tepi (*stroke*) sewarna tema. Tombol aksi sekunder, filter pencarian, atau navigasi pagination.
Ghost / Text Button Hanya teks tanpa bingkai; background baru muncul saat kursor hover. Aksi netral ringan (*'Batal'*, *'Tutup'*, *'Lewati Langkah'*).
Destructive / Danger Button Warna merah terang (`#EF4444`). Aksi permanen berisiko tinggi (*'Hapus Database'*, *'Keluar Akun'*).
Icon Button Bentuk 40x40px hanya berisi simbol ikon grafis. Bilah toolbar sempit. Wajib menyertakan atribut aksesibilitas aria-label.
Split / Dropdown Button Tombol terbelah (klik kiri = aksi cepat, klik kanan panah = menu opsi). Aksi majemuk (contoh: *'Publikasikan'* vs *'Jadwalkan Besok'*).

Kategori 3: Kontrol Formulir & Input Data (Form Controls)

Komponen penangkap input teks, pilihan numerik, tanggal, dan berkas dari pengguna.

Kontrol Input Fungsi Spesifik Contoh Skenario Nyata
Text Input (Single Line) Masukan teks pendek 1 baris. Nama lengkap pelanggan, alamat email, kode kupon diskon.
Password Field Teks tersensor titik dengan tombol mata (*toggle show/hide*). Formulir login dan pembuatan kata sandi baru.
Textarea (Multi Line) Kotak teks luas yang dapat di-scroll atau resize. Catatan kurir pengiriman, ulasan testimoni pembeli produk.
Select / Dropdown Pemilih 1 opsi dari daftar tersembunyi yang hemat ruang layar. Pilihan Provinsi pengiriman, pilihan metode kurir ekspedisi.
Combobox / Autocomplete Kotak ketik dengan pencarian in-memory dinamis. Pencarian nama kecamatan / kelurahan dari 80.000+ data wilayah.
Checkbox Pemilih multi-pilihan (bisa memilih 0, 1, atau banyak opsi sekaligus). Pilihan filter produk: [x] Gratis Ongkir [x] Bintang 4+ [x] COD.
Radio Button Pemilih opsi tunggal mutlak yang mutually exclusive. Pilihan metode pembayaran: (o) QRIS ( ) Transfer Bank ( ) COD.
Toggle Switch Saklar geser on/off instan tanpa perlu tombol 'Simpan'. Pengaturan sistem: Aktifkan Mode Gelap, Nyalakan Notifikasi Push.
Range Slider Penggeser nilai numerik kontinu. Filter rentang harga: Rp 50.000 s/d Rp 2.500.000.
OTP / Pin Input Deretan 4-6 kotak kecil terpisah yang otomatis lompat ke kotak berikutnya. Verifikasi keamanan 2FA SMS/WhatsApp kode OTP.
File Dropzone Area drag-and-drop berkas dokumen atau gambar. Unggah bukti transfer pembayaran atau foto KTP verifikasi.

Kategori 4: Umpan Balik & Notifikasi (Feedback & Overlays)

Komponen penunjuk status operasi, pemberi peringatan, dan dialog aksi mendesak.

Komponen Feedback Tingkat Gangguan (*Disruption*) Waktu & Skenario Muncul
Toast / Snackbar Rendah (Non-blocking): Melayang di sudut layar, hilang otomatis dalam 3-5 detik. Konfirmasi aksi sukses instan (contoh: 'Link berhasil disalin ke clipboard').
Alert Banner / Callout Sedang (In-page): Kotak berwarna statis di dalam alur halaman. Peringatan akun belum diverifikasi atau panduan tips keamanan.
Modal Dialog Sangat Tinggi (Blocking): Membekukan seluruh layar dengan backdrop gelap. Persetujuan penting yang tidak boleh diabaikan (*'Konfirmasi Hapus Data'*).
Drawer / Bottom Sheet Tinggi (Slide-in): Panel geser dari sisi layar atau bagian bawah smartphone. Keranjang belanja kilat, filter produk kompleks di mobile, atau form komentar.
Tooltip Mikro (On Hover/Focus): Gelembung teks kecil saat mouse mendekat. Menjelaskan arti tombol yang hanya berupa ikon tanpa teks label.
Skeleton Loader Persepsi Positif: Kerangka shimmer abu-abu yang meniru bentuk asli konten. Saat aplikasi sedang menunggu respons API data jaringan asinkron.

Kategori 5: Penyajian & Pengelompokan Data (Data Display)

Komponen perangkum informasi agar data besar mudah dicerna otak pengguna secara cepat.

Komponen Tampilan Karakter Desain Contoh Penggunaan Industri
Bento Card Kartu modular dengan elevasi, radius halus, dan perpaduan hierarki visual tegas. Menampilkan kartu ringkasan fitur produk, kartu modul belajar, atau metrik KPI.
Data Table Tabel baris-kolom dengan sticky header, pagination, dan fungsi pengurutan (*sorting*). Daftar transaksi order e-commerce, laporan keuangan, log aktivitas pengguna.
Badge / Status Pill Lencana oval kecil berwarna kontras dengan teks singkat. Penunjuk status real-time (*'Aktif'*, *'Selesai'*, *'Gagal'*, *'Diskon 50%'*).
Avatar Group Tumpukan foto profil bulat bertingkat yang saling tumpang-tindih. Menampilkan anggota tim proyek atau kolaborator yang sedang online.
Accordion / Collapse Panel bertingkat yang mengembang saat diklik untuk menghemat ruang vertikal. Halaman Tanya Jawab (*FAQ*), spesifikasi teknis, atau filter kategori samping.
Timeline Garis vertikal/horizontal historis dengan titik simpul kejadian. Pelacakan paket kurir pengiriman e-commerce atau riwayat audit log.
Empty State Ilustrasi ramah dengan teks panduan saat data masih kosong. Tampilan ketika keranjang belanja masih 0 barang atau kotak masuk belum ada pesan.

3. CSS Grid vs Flexbox: Panduan Keputusan Arsitektur

Salah satu kesalahan paling mendasar frontend engineer adalah memaksakan Flexbox untuk mengatur seluruh halaman, atau menggunakan Grid untuk hal-hal sepele. Berikut adalah aturan baku industri:

Contoh Visual Nyata: CSS Flexbox (1D) vs CSS Grid (2D)
Render Langsung
Flexbox 1-Dimensi (Main Axis: space-between)
Velora App

Elemen fleksibel menyejajarkan diri secara horizontal pada satu baris.

CSS Grid 2-Dimensi (Bento Matrix: 2 Kolom x 2 Baris)
Item A (1x1)
Item B (1x1)
Item C (Span 2 Kolom Penuh)

Elemen C melintasi 2 kolom sekaligus membentuk struktur Bento.

Parameter CSS Flexbox (1-Dimensi) CSS Grid (2-Dimensi)
Dimensi Kerja Hanya satu sumbu dalam satu waktu: Baris (horizontal) ATAU Kolom (vertikal). Dua sumbu sekaligus: Mengontrol baris DAN kolom secara presisi bersamaan.
Pendekatan Desain Content-First: Elemen menentukan ukurannya sendiri, lalu Flexbox merapikan posisinya. Layout-First: Kerangka grid ditentukan terlebih dahulu, lalu elemen ditempatkan ke dalam sel yang tersedia.
Kasus Penggunaan Ideal
  • Navbar item (Logo di kiri, Menu di tengah, Profil di kanan).
  • Tombol dengan ikon di samping teks (`gap: 8px`).
  • Penyelarasan vertikal elemen (`align-items: center`).
  • Katalog produk e-commerce (`grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))`).
  • Bento Grid Dashboard modern.
  • Layout utama halaman (Sidebar + Main Content + Header).
modern-layout.css — Standar Bento Grid Auto-Responsive 
/* 1. CSS Grid untuk Katalog / Bento Grid Responsif */
.bento-grid {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(300px, 1fr));
    gap: 1.5rem; /* 24px via 8pt grid token */
}

/* 2. Flexbox untuk Komponen Mikro di dalam Kartu */
.bento-card-header {
    display: flex;
    justify-content: space-between;
    align-items: center;
    gap: 0.75rem; /* 12px */
}

Header / App Bar

Header adalah kompas navigasi utama. Standar arsitektur header kelas dunia:

  • Sticky vs Fixed: Gunakan position: sticky; top: 0; z-index: 1000; agar header tetap terlihat saat scroll tanpa menutupi konten di bawahnya saat load awal.
  • Glassmorphism Backdrop: Gunakan backdrop-filter: blur(16px); background: rgba(11, 19, 43, 0.85); agar konten di balik header tampak elegan saat discroll.
  • Mobile Hamburger: Pada layar <768px, menu horizontal disembunyikan dan dialihkan ke drawer overlay.

Hero Section / Masthead

Area Above-the-Fold yang pertama kali dirender browser. Anatomi wajib Hero:

  • Social Proof Badge: Bukti kepercayaan (contoh: "Dipercaya oleh 10.000+ Engineer").
  • Display H1 (Bold Value Proposition): Maksimal 8-12 kata yang menjawab: "Apa produk ini dan apa untungnya bagi saya?".
  • Sub-headline (Body Lead): Penjelasan 1-2 kalimat pendukung H1.
  • Dual Action Buttons: 1 Primary CTA (Beli / Daftar) + 1 Secondary CTA (Lihat Demo / Dokumentasi).

6. Sidebar Navigation (Drawer vs Rail)

Ketika sebuah aplikasi memiliki lebih dari 10 fitur utama, menu atas (*header*) tidak akan muat lagi. Di sinilah peran Sidebar:

Contoh UI Nyata: Navigation Rail (64px) vs Expanded Sidebar (240px)

Tipe Sidebar Lebar Khas Karakteristik & Skenario Penggunaan
Expanded Sidebar 240px - 280px Menampilkan ikon dan teks lengkap secara permanen. Umum pada dashboard laptop/desktop monitor lebar.
Navigation Rail (Collapsed) 64px - 72px Hanya menampilkan deretan ikon vertikal untuk menghemat ruang kerja kanvas (misal: Slack, VS Code, Figma). Teks label muncul via tooltip saat hover.
Off-Canvas Drawer (Mobile) 80% - 100% viewport Tersembunyi di luar layar kiri/kanan (`transform: translateX(-100%)`) dan bergeser muncul saat tombol hamburger diklik dengan overlay gelap di belakangnya.

8. Kuis Uji Pemahaman Komponen Layout

1. Kapan seorang frontend engineer wajib memilih CSS Grid daripada Flexbox?
A. Saat ingin menyejajarkan ikon di sebelah teks tombol
B. Saat membangun struktur 2-dimensi yang mengontrol baris dan kolom secara serentak seperti katalog produk atau dashboard Bento Grid
C. Saat ingin mengatur tinggi tombol secara otomatis
2. Mengapa sebuah halaman web modern harus memiliki batas 'max-width' pada containernya (misal 1280px) dan tidak dibiarkan melar 100% di monitor 4K?
A. Menjaga keterbacaan teks dan kenyamanan motorik mata agar pengguna tidak perlu menolehkan kepala dari ujung kiri ke ujung kanan monitor ultrawide
B. Karena browser akan mengalami crash jika merender lebih dari 1920 piksel
C. Untuk menghemat konsumsi kuota data internet
