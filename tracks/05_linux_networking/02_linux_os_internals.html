Apa Ini Sebenarnya?

Kernel Linux adalah penguasa tertinggi di dalam server yang mengatur pembagian jatah waktu prosesor (CPU) dan ruang memori (RAM) untuk semua program.

Masalah Nyata Apa yang Diselesaikan?

Jika tidak ada kernel yang tegas, satu program yang eror atau rakus bisa menghabiskan seluruh memori komputer dan membekukan seluruh server.

Analogi Kehidupan Sehari-Hari

Ibarat kepala sekolah yang membagi jatah lapangan olahraga: setiap kelas diberi giliran bermain 45 menit secara adil agar tidak ada murid yang memonopoli lapangan seharian.

Kapan Kita Memakainya?

Wajib dipahami oleh Backend & DevOps Engineer untuk mengoptimalkan kinerja server produksi dan melacak penyebab server hang atau kehabisan memori.

Modul 18: Linux OS Internals: Proses, File Descriptors & epoll

Membongkar rahasia di balik efisiensi sistem operasi Linux: perbedaan struktur memori Proses vs Thread, filosofi UNIX "Everything is a File", arsitektur I/O Multiplexing epoll yang menaklukkan C10K Problem, perbandingan mutakhir dengan io_uring, serta kalkulasi izin berkas oktal.

1. Proses vs Thread di Ruang Memori Linux

Bagaimana kernel Linux mengelola program yang berjalan?

Proses (Process)
• Memiliki ruang memori virtual (Virtual Address Space) yang terisolasi 100%: segmen Text (kode), Data, BSS, Heap, dan Stack.
• Jika satu proses crash (Segmentation Fault), proses lain di OS tetap hidup aman.
• Biaya pembuatan (fork) dan pergantian konteks (*Context Switching*) relatif mahal.
Thread (Lightweight Process)
• Berjalan di dalam satu proses yang sama.
• Berbagi ruang Heap dan Data bersama, namun masing-masing thread memiliki Stack dan Register CPU sendiri.
• Sangat cepat berpindah konteks, namun rentan bahaya Race Condition jika variabel memori diubah serentak tanpa mutex lock!

2. Filosofi UNIX: "Everything is a File" & VFS

Di Linux, hampir semua hal diwakili sebagai sebuah file: berkas teks biasa di SSD, port jaringan TCP socket, keyboard, mouse, bahkan pipa komunikasi data (*Pipes*).

Peran Virtual File System (VFS)
VFS adalah lapisan abstraksi kernel yang menyediakan antarmuka standar: open(), read(), write(), close().

Program aplikasi Anda tidak perlu peduli apakah berkas disimpan di format filesystem ext4, XFS, NFS jaringan, atau membaca byte dari socket jaringan TCP. VFS menerjemahkan seluruh syscall tersebut secara transparan!

3. File Descriptors (FD) dan Nilai Standar (0, 1, 2)

Setiap kali proses membuka berkas atau koneksi socket, kernel memberikan sebuah integer bilangan bulat positif yang disebut File Descriptor:

FD Integer Nama Standar POSIX Tujuan Aliran Data
0 stdin (Standard Input) Input teks dari keyboard atau pipa (pipe)
1 stdout (Standard Output) Output teks normal ke terminal monitor
2 stderr (Standard Error) Output pesan kesalahan darurat ke monitor
3, 4, 5... Custom File / Sockets File di disk atau socket koneksi pengguna Nginx/Node.js

4. Solusi Masalah C10K: select vs epoll vs io_uring

Pada tahun 1999, server web lumpuh ketika harus menangani 10.000 koneksi bersamaan (The C10K Problem). Bagaimana kernel Linux berevolusi menaklukkannya?

Generasi 1
select() / poll()
Kompleksitas O(N). Kernel memindai seluruh 10.000 array socket satu per satu di setiap loop. Sangat lambat dan memakan 100% CPU!
Generasi 2
epoll() (Linux 2.6+)
Kompleksitas O(1)! Menggunakan Red-Black Tree di kernel dan hanya mengembalikan daftar socket yang benar-benar siap (Ready List). Fondasi Nginx dan Node.js!
Generasi 3
io_uring (Linux 5.1+)
Zero-Syscall Asynchronous I/O! Menggunakan shared ring-buffer SQ/CQ antara user space dan kernel. Standar performa baru sistem modern!

5. Matematika Izin Berkas Linux (chmod Oktal)

Izin berkas Linux dihitung berdasarkan bobot biner tiga jenis izin:
Read (r) = 4 • Write (w) = 2 • Execute (x) = 1

chmod 755 (Standar Web Executable)
• Owner: 7 (4 + 2 + 1 = rwx → Baca, Tulis, Eksekusi)
• Group: 5 (4 + 0 + 1 = r-x → Baca, Eksekusi)
• Others: 5 (4 + 0 + 1 = r-x → Baca, Eksekusi)
chmod 600 (Kunci Rahasia SSH / .env)
• Owner: 6 (4 + 2 + 0 = rw- → Baca, Tulis)
• Group: 0 (--- → Dilarang Akses)
• Others: 0 (--- → Dilarang Akses)

6. Production War Stories & Anti-Patterns

War Story: Server Crash Jam 12 Malam dengan Error "Too many open files"
Sebuah server backend Node.js menerima lonjakan trafik flash sale 20.000 pengguna secara serempak. Mendadak aplikasi crash total dan log terminal memuntahkan ribuan error: Error: EMFILE: too many open files.

Penyebab: Di Linux, setiap koneksi socket TCP yang masuk dianggap sebagai 1 File Descriptor. Secara default, Linux membatasi batas maksimum file descriptor per proses sebesar 1024 (ulimit -n 1024)! Begitu ada 1.025 pengguna yang tersambung, kernel menolak membuat socket baru!

Solusi Produksi: Tingkatkan batas limit file descriptor di /etc/security/limits.conf atau systemd service:
LimitNOFILE=65535
