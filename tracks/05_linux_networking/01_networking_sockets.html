Apa Ini Sebenarnya?

Socket adalah ujung colokan pipa virtual di sistem operasi yang menghubungkan program Anda dengan kabel jaringan internet dunia.

Masalah Nyata Apa yang Diselesaikan?

Tanpa socket dan nomor port, komputer tidak tahu apakah paket data YouTube yang masuk harus diserahkan ke browser, Spotify, atau game online Anda.

Analogi Kehidupan Sehari-Hari

Ibarat menelepon kantor gedung megah: alamat IP adalah nomor telepon gedung, sedangkan nomor PORT adalah nomor ekstensi ruangan staf spesifik yang ingin Anda tuju.

Kapan Kita Memakainya?

Dibutuhkan saat membangun chat real-time, game multiplayer online, server web berkecepatan tinggi, dan diagnosa koneksi server terputus.

Setiap kali browser Anda mengirimkan satu request HTTP, data tersebut dibungkus (enkapsulasi) lapis demi lapis ke dalam header jaringan sebelum menjadi sinyal elektromagnetik di kabel:

2. Alamat IP & Matematika Subnetting Notasi CIDR

Alamat IPv4 terdiri dari 32 bit biner (4 oktet). Notasi CIDR (Classless Inter-Domain Routing) menentukan berapa banyak bit yang dialokasikan untuk ID Jaringan (Network) dan berapa bit yang tersisa untuk ID Host (Server):

Menghitung Kapasitas Subnet 192.168.1.0/24
• /24 berarti 24 bit pertama adalah Network ID prefix.
• Sisa bit untuk Host: 32 - 24 = 8 bit.
• Total IP di subnet: 2^8 = 256 alamat IP.
• IP yang Dapat Dipakai Host: 256 - 2 = 254 IP (Alamat .0 dicadangkan untuk Network Address, dan alamat .255 dicadangkan untuk Broadcast Address).

3. Perjalanan Kueri Rekursif DNS: Dari Domain ke IP

Ketika Anda mengetikkan google.com di peramban, komputer Anda tidak tahu ke server mana harus tersambung sebelum melakukan resolusi hierarkis DNS:

Langkah 1
Browser / OS Cache
Memeriksa memori lokal atau berkas /etc/hosts.
Langkah 2
DNS Resolver (ISP)
Kueri dikirim ke server resolver rekursif (misal Cloudflare 1.1.1.1).
Langkah 3
Root Server (.)
Mengarahkan ke server TLD yang bertanggung jawab untuk domain .com.
Langkah 4
Authoritative NS
Server nameserver pemilik domain mengembalikan IP target (A / AAAA Record) dengan TTL.

4. Anatomi TCP 3-Way Handshake & 4-Way Teardown

Sebelum 1 byte pun data HTTP dapat dikirim, client dan server wajib menyepakati nomor urut sequence number (ISN):

TCP 3-Way Handshake (Membuka Sesi)
1. Client → Server: [SYN] (Seq=100) — "Halo, saya ingin membuka koneksi."
2. Server → Client: [SYN, ACK] (Seq=300, Ack=101) — "Diterima! Saya juga siap."
3. Client → Server: [ACK] (Seq=101, Ack=301) — "Konfirmasi! Koneksi ESTABLISHED."
TCP 4-Way Teardown (Menutup Sesi)
1. Client → Server: [FIN] — "Saya selesai mengirim data."
2. Server → Client: [ACK] — "FIN diterima."
3. Server → Client: [FIN] — "Saya juga sudah selesai."
4. Client → Server: [ACK] — Client masuk ke status TIME_WAIT (biasanya 60 detik) untuk memastikan ACK sampai.

5. Linux Berkeley Sockets API: Siklus Hidup Socket Server

Di tingkat kernel sistem operasi, seluruh server web (Nginx, Express, Apache) berkomunikasi melalui urutan 5 panggilan sistem (syscall) Berkeley Sockets:

Siklus Panggilan Syscall Socket di Linux
// 1. Buat socket endpoint di kernel
int server_fd = socket(AF_INET, SOCK_STREAM, 0);

// 2. Ikat (bind) socket ke alamat IP dan nomor Port lokal
bind(server_fd, (struct sockaddr*)&server_addr, sizeof(server_addr));

// 3. Masuk ke mode pasif menunggu koneksi masuk (listen queue backlog)
listen(server_fd, 128);

while (1) {
    // 4. Menerima koneksi baru yang sudah selesai 3-Way Handshake
    // Mengembalikan File Descriptor (client_fd) BARU khusus untuk klien ini!
    int client_fd = accept(server_fd, (struct sockaddr*)&client_addr, &addr_len);
    
    // 5. Baca dan Tulis data
    read(client_fd, buffer, 1024);
    write(client_fd, "HTTP/1.1 200 OK\r\n\r\nHello World", 30);
    close(client_fd);
}

6. Production War Stories & Anti-Patterns

War Story: Kehabisan Port Ephemeral Akibat Banjir Socket TIME_WAIT
Sebuah layanan backend microservice menembak API pembayaran eksternal jutaan kali per jam. Namun di setiap request, developer membuka koneksi TCP baru dan langsung menutupnya (Connection: close).

Setelah berjalan 3 jam, server tiba-tiba crash dengan pesan error: "Cannot assign requested address" (EADDRNOTAVAIL)!

Penyebab: Setiap socket yang ditutup oleh client masuk ke status TIME_WAIT selama 60 detik untuk mencegah paket tersasar merusak koneksi baru. Karena ada 60.000 request per menit, seluruh 65.535 port keluar (ephemeral ports) habis terkunci di status TIME_WAIT!

Solusi: Aktifkan HTTP Connection Pooling / Keep-Alive (Upstream Keepalive) sehingga ratusan request menggunakan kembali koneksi TCP yang sudah terbuka tanpa membuka-tutup socket berulang kali!
