Modul 24: Manajemen Memori: Stack vs Heap, GC & Rust Ownership

Fondasi alokasi data di tingkat biner: perbedaan kecepatan perangkat keras Stack LIFO vs dinamika Heap, algoritma Generational Garbage Collection (V8 Scavenger nursery copying & Mark-Sweep-Compact), serta paradigma revolusioner Rust Compile-Time Ownership & Borrow Checker tanpa runtime GC pauses.

Fondasi Konsep: Manajemen Memori & Garbage Collection
Ibarat Petugas Kebersihan Otomatis di Restoran
Apa Ini Sebenarnya?

Mekanisme pembersihan otomatis yang mendaur ulang ruang RAM yang sudah tidak dipakai lagi oleh variabel program agar memori komputer tetap lega.

Masalah Nyata Apa yang Diselesaikan?

Tanpa pembersihan memori (Memory Leak), RAM server akan perlahan membengkak hingga akhirnya sistem operasi kehabisan memori dan aplikasi mati mendadak.

Analogi Kehidupan Sehari-Hari

Ibarat pelayan restoran yang sigap mengangkat piring kotor saat pelanggan selesai makan: jika piring kotor dibiarkan menumpuk, meja akan penuh dan tamu baru tidak bisa duduk.

Kapan Kita Memakainya?

Wajib dikuasai untuk mencegah memory leak di aplikasi backend Node.js, aplikasi mobile Flutter/React Native, atau game berdurasi panjang.

1. Anatomi Memori: Stack vs Heap

Ketika program dieksekusi oleh sistem operasi, memori RAM dibagi menjadi dua struktur penyimpanan utama:

Karakteristik Stack Memory Heap Memory
Struktur Data LIFO (Last-In, First-Out) berurutan Alokasi Dinamis Bebas (Hierarki Pohon / Blok Terfragmentasi)
Kecepatan Alokasi Super Kilat (1 instruksi CPU Stack Pointer) Lebih lambat (Mencari blok memori kosong yang pas via OS allocator)
Ukuran Variabel Wajib diketahui ukurannya secara pasti saat compile time Dinamis dan fleksibel (Array yang ukurannya bisa bertambah)
Siklus Hidup (Lifetime) Otomatis terhapus begitu fungsi selesai (Return) Harus dibebaskan manual (C/C++ free), via Garbage Collector (JS/Java/Go), atau via RAII (Rust)

2. Pointer: Alamat Memori Nyata

Pointer Hanyalah Nomor Rumah di RAM
Pada prosesor 64-bit, sebuah Pointer hanyalah integer 8-byte (64-bit) yang menyimpan alamat heksadesimal RAM (misalnya 0x7ffee4b2a1c0).

• Variabel lokal pointer disimpan di Stack.
• Objek data besar yang ditunjuk oleh pointer tersebut berada di Heap.

3. Generational Garbage Collection: "Most Objects Die Young"

Bagaimana runtime seperti V8 (JavaScript) atau Go membersihkan memori Heap tanpa memory leak? Mereka memanfaatkan Generational Hypothesis: sebagian besar objek hanya berumur beberapa milidetik (misal variabel lokal di dalam callback).

Generasi Muda
Nursery (Semi-Space)
Objek baru dialokasikan di sini. Dicuci kilat oleh Scavenger GC (~1-2ms). Objek hidup disalin ke ruang sebelah; sisanya dibuang.
Promosi
Intermediate Space
Jika objek bertahan melewati 2 kali putaran Scavenger, objek dipromosikan ke Old Generation.
Generasi Tua
Old Generation
Dibersihkan dengan Major Mark-Sweep-Compact. Lebih jarang dijalankan karena memicu jeda *Stop-The-World (STW)*.

4. Revolusi Rust: Zero-Cost Abstraction Tanpa Garbage Collector!

Bahasa Rust membuktikan bahwa kita bisa memiliki keamanan memori 100% tanpa membayar ongkos performa Garbage Collector melalui 3 Aturan Kepemilikan (Ownership Rules):

3 Hukum Suci Kepemilikan Rust
1. Setiap nilai di memori Rust memiliki satu variabel yang menjadi Owner-nya.
2. Hanya boleh ada SATU Owner pada satu saat.
3. Ketika variabel Owner keluar dari cakupan (out of scope), memori di-drop secara otomatis oleh kompiler (prinsip RAII)!
Move Semantics di Rust
let s1 = String::from("halo");
// Kepemilikan berpindah (MOVE) ke s2:
let s2 = s1; 

// COMPILE ERROR! s1 sudah hangus!
// Tidak ada double-free bug!
println!("{}", s1);

5. The Borrow Checker: Aliasing XOR Mutability

Bagaimana jika fungsi lain ingin membaca data tanpa mengambil alih kepemilikan? Anda boleh Meminjam (Borrowing) dengan aturan:

Hukum Eksklusivitas Pinjaman Rust
Pada satu titik waktu yang sama, Anda boleh memiliki:
• Banyak referensi baca yang tidak bisa mengubah data (&T), ATAU
• TEPAT SATU referensi eksklusif yang bisa mengubah data (&mut T).

TETAPI TIDAK PERNAH KEDUANYA SEKALIGUS! Aturan matematika ini mengeliminasi Data Race dan Dangling Pointers saat kompilasi tanpa membutuhkan runtime lock!

6. Production War Stories & Anti-Patterns

War Story: Discord Migrasi Layanan Read States dari Go ke Rust Mengatasi Jeda GC
Discord memiliki layanan "Read States" yang mencatat pesan mana yang sudah dibaca oleh ratusan juta pengguna. Layanan ini awalnya dibangun dengan bahasa Go.

Masalah: Setiap 2 menit sekali, Garbage Collector Go melakukan siklus pemindaian memori pada cache berisi miliaran objek kecil. Hal ini menimbulkan lonjakan latensi (*Latency Spike*) hingga 800 milidetik yang membuat suara dan status pesan tersendat!

Solusi: Discord menulis ulang layanan tersebut menggunakan Rust. Karena Rust mengalokasikan dan membebaskan memori secara deterministik tanpa Garbage Collector, grafik latensi seketika berubah menjadi garis datar stabil di bawah 1 milidetik tanpa lonjakan sama sekali!
