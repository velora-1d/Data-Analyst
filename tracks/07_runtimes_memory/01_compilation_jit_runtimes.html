Modul 23: Paradigma Bahasa & Eksekusi: Kompilasi vs Interpreter vs JIT

Bagaimana teks kode program berubah menjadi instruksi biner CPU: spektrum kompilasi Ahead-of-Time (C/Rust/Go) vs Interpreter baris-per-baris (Python klasik) vs Just-In-Time (JIT) V8 Engine (Ignition bytecode interpreter & TurboFan optimizing compiler), serta pencegahan penalti Deoptimasi.

1. Tiga Model Eksekusi Bahasa Pemrograman

Komputer pada dasarnya hanyalah mesin penghitung biner (Machine Code 0 dan 1) yang diatur oleh instruksi set prosesor (x86_64 / ARM64). Bahasa pemrograman tingkat tinggi harus dijembatani ke mesin fisik melalui salah satu dari 3 cara:

Model Eksekusi Contoh Bahasa Kapan Diterjemahkan? Kelebihan & Trade-off
AOT (Ahead-of-Time) C, C++, Rust, Go Sebelum eksekusi (Kompilasi ke binary native OS) Kecepatan maksimum, konsumsi RAM kecil, namun proses build lambat dan binary tidak portabel lintas OS.
Interpreter Murni Bash, Ruby klasik, Python lama Secara langsung saat program berjalan baris demi baris Sangat fleksibel, start time cepat, namun kecepatan eksekusi lambat (10x-50x lebih lambat dari C).
JIT (Just-In-Time) JavaScript (V8), Java (JVM), C# (.NET CLR) Kombinasi: Mulai dari Interpreter, lalu fungsi yang sering dipanggil dikompilasi ke Native Machine Code saat runtime! Keseimbangan emas: Portabel seperti script, namun mendekati kecepatan C saat program sudah berjalan panas (*warm up*).

2. Mengapa JavaScript Tidak Bisa Menggunakan AOT Murni?

Bahasa seperti C atau Rust bersifat Statically Typed: compiler tahu pasti bahwa variabel x adalah integer 32-bit di alamat memori tertentu.

Sebaliknya, JavaScript bersifat Dynamically Typed:

Dilema Dinamis JS
function tambah(a, b) {
    return a + b; // Apakah ini penjumlahan angka? Atau penggabungan string?
}
tambah(5, 10);     // 15 (Number addition CPU opcode ADD)
tambah("Halo ", "Dunia"); // "Halo Dunia" (String concatenation CPU memory alloc)

Karena tipe data bisa berubah-ubah sesuka hati pengguna saat runtime, compiler tidak bisa menghasilkan kode mesin CPU statis di awal tanpa melakukan inspeksi dinamis!

3. Mesin V8 Modern: Duet Ignition & TurboFan

Google mendesain mesin V8 (di Chrome dan Node.js) dengan arsitektur dua tahap yang sangat brilian:

Tahap 1
Ignition (Interpreter)
Mengubah kode JS menjadi Bytecode ringkas dan menjalankannya seketika. Mengumpulkan profil tipe data (*Type Feedback Vectors*).
Tahap 2
Profiler (Hot Detection)
Mendeteksi fungsi mana yang dipanggil berulang-ulang ribuan kali (*Hot Function*).
Tahap 3
TurboFan (JIT Compiler)
Menerjemahkan bytecode fungsi panas tersebut menjadi Machine Code Assembler mentah yang super kencang!

4. Bahaya Deoptimasi (Deopt Bailout) & Polimorfisme

TurboFan melakukan optimasi spekulatif: "Fungsi tambah(a, b) ini sudah dipanggil 10.000 kali selalu dengan angka integer. Saya akan buatkan kode mesin CPU murni khusus integer!"

Skenario Deoptimasi (Bailout)
Mendadak pada panggilan ke 10.001, developer memanggil: tambah("teks", 5)!

Asumsi spekulatif TurboFan hancur berantakan. V8 terpaksa membuang machine code yang sudah dioptimasi dan mundur kembali ke bytecode Ignition (*Deoptimization Bailout*).

Aturan Kinerja V8: Tulis kode yang Monomorfik (Bentuk Objek dan Tipe Argumen Selalu Konsisten)! Objek yang bentuk propertinya diubah-ubah secara dinamis (Polimorfik / Megamorfik) akan menghancurkan performa JIT engine hingga 5x lipat.

6. Production War Stories & Anti-Patterns

War Story: Menghapus Properti dengan `delete obj.prop` Melumpuhkan Hidden Classes V8
Sebuah layanan analitik data real-time menggunakan kata kunci JavaScript: delete objek.sensitif_key untuk membersihkan field sebelum dikirim ke client.

Ketika throughput mencapai 50.000 data per detik, performa server anjlok drastis dan CPU membara 100%.

Penyebab: V8 mengoptimalkan objek JS menggunakan Hidden Classes (Shapes) di balik layar. Menghapus properti menggunakan delete secara paksa merusak transisi shape objek dan mengubahnya menjadi mode kamus lambat (*Slow Dictionary Mode*), mematikan seluruh optimasi inline cache TurboFan!

Solusi Baku: Jangan pernah gunakan delete di dalam hot loop! Cukup set nilainya menjadi undefined atau buat objek baru yang bersih secara eksplisit.
