Modul 09: Paradigma Frontend Framework & State Management

Membedah filosofi di balik framework JavaScript modern: Virtual DOM Diffing (React) vs Compile-Time Code Generation (Svelte) vs Fine-Grained Signals (SolidJS/Vue/Angular), evaluasi model rendering web dari CSR hingga Islands Architecture, dan pemisahan arsitektur Client State vs Server Cache.

Fondasi Konsep: Paradigma Framework Modern (React/Vue/Svelte)
Ibarat Robot Asisten Pengubah Perabotan
Apa Ini Sebenarnya?

Framework UI adalah alat bantu canggih yang secara otomatis memperbarui tampilan layar setiap kali ada data baru yang masuk tanpa perlu kita utak-atik manual.

Masalah Nyata Apa yang Diselesaikan?

Di masa lalu, programmer harus mengetik 10 baris kode rumit hanya untuk mengganti angka notifikasi. Framework menyederhanakannya menjadi 1 baris deklarasi yang bersih.

Analogi Kehidupan Sehari-Hari

Ibarat papan skor digital sepak bola: wasit cukup mengetik angka skor '1-0', dan papan lampu raksasa otomatis menyala sendiri tanpa perlu teknisi memanjat tangga mengganti bohlam.

Kapan Kita Memakainya?

Dipakai saat membangun aplikasi interaktif modern dengan banyak data yang sering berubah, seperti dashboard analitik, feed media sosial, atau formulir bertingkat.

1. Mengapa Kita Butuh Reaktivitas UI?

Di era jQuery atau JavaScript Vanilla mentah, developer harus menulis manipulasi DOM imperatif secara manual:

Kode Imperatif Tradisional
// Setiap kali data berubah, developer harus mencari elemen DOM dan mengubahnya manual
count += 1;
document.getElementById('counterDisplay').textContent = count;
if (count > 10) {
    document.getElementById('badgeWarning').classList.add('visible');
}

Pada aplikasi skala besar dengan ribuan elemen, pendekatan imperatif ini rentan menghasilkan Inconsistent UI Bugs: ada elemen yang lupa di-update saat state berubah.
Framework modern menawarkan Deklaratif UI: UI = f(State). Ketika State bermutasi, tampilan UI otomatis menyesuaikan diri secara otomatis.

2. Tiga Mazhab Besar Paradigma Reaktivitas

Mazhab Reaktivitas Contoh Framework Mekanisme Kerja Internal Ukuran Runtime & Trade-off
Virtual DOM Diffing React 19 Membuat pohon objek JS virtual di memori, membandingkan (diffing) dengan pohon sebelumnya (Fiber reconciliation), lalu menambal perbedaan ke real DOM. Ukuran bundle sedang (~45KB), re-render seluruh subtree kecuali di-memoize manual.
Compile-Time Reactivity Svelte 5 (Runes) Tanpa Virtual DOM! Kompiler mengubah sintaks reaktif pada saat build menjadi manipulasi DOM JavaScript murni yang super efisien. Ukuran runtime sangat mungil (~3-5KB), performa awal kilat.
Fine-Grained Signals SolidJS, Vue 3, Angular 20 Variabel diikat dalam dependency graph (Pub/Sub). Ketika signal berubah, hanya node teks/elemen spesifik yang terhubung langsung yang diubah secara O(1)! Kecepatan runtime nomor 1 di industri, bundle hemat (~7KB), zero diffing overhead.

3. Mengapa Industri Frontend Berkonvergensi ke "Signals"?

Pada framework Virtual DOM seperti React, ketika sebuah state di komponen induk berubah, seluruh fungsi komponen beserta seluruh anak-anaknya di bawah pohon akan dipanggil ulang (re-rendered):

Model Mental Signals: Bedah O(1) Surgical Update
Pada model Signals (SolidJS, Vue, Angular):

1. Fungsi komponen HANYA BERJALAN 1 KALI SEUMUR HIDUP saat inisialisasi awal.
2. Getter signal (misal count()) otomatis mencatat subscriber mana yang membacanya.
3. Ketika setCount(count() + 1) dipanggil, framework tidak menjalankan ulang fungsi komponen. Framework melompat langsung ke satu TextNode spesifik di DOM via pointer memori dan menimpa teksnya secara instan!

Inilah alasan mengapa SolidJS secara konsisten mengalahkan React dalam benchmark kecepatan CPU manipulasi tabel data.

4. Spektrum Model Rendering: CSR s/d Islands Architecture

CSR
Client-Side Rendering
HTML kosong, JS bundle besar dikirim ke browser untuk merender layar. Cocok untuk dashboard privat.
SSR
Server-Side Rendering
Server merender HTML penuh per request. Bagus untuk SEO & First Contentful Paint. Butuh server compute.
SSG
Static Site Generation
HTML dipanggang saat build time. Disajikan instan dari CDN (0ms TTFB). Seperti modul portal kita saat ini!
Islands
Islands Architecture (Astro)
Halaman 95% murni HTML statis, hanya komponen interaktif tertentu (pulau) yang di-hidrasi JavaScript.

5. Arsitektur State: Client State vs Server Cache State

Salah satu kesalahan arsitektur terbesar di kalangan pengembang adalah mencampuradukkan Client State dengan Server State ke dalam satu global store besar (seperti Redux monolitis):

Anti-Pattern: Manual Redux untuk Data API
• Menaruh data produk dari server ke dalam Redux/Zustand secara manual.
• Developer harus mengelola state isLoading, isError, dan data sendiri.
• Tidak ada deduplikasi request: 3 komponen yang butuh data user akan menembak 3 kali fetch ke server.
• Data cepat basi (stale) jika tidak di-refetch manual.
Modern Architecture: Server State Caching
• Gunakan TanStack Query (React Query / SWR).
• Stale-While-Revalidate: Tampilkan data cache instan, perbarui di latar belakang.
• Query Deduplication: 5 komponen meminta user yang sama → hanya 1 network request!
• Auto-refetch saat window kembali aktif (window focus refetching).

6. Lab Hands-on: Membangun Mini Reactivity Engine Berbasis Proxy

Bagaimana cara kerja library reaktivitas modern seperti Vue 3 atau MobX di balik layar? Mari kita bangun mesin reaktif sederhana menggunakan JavaScript ES6 Proxy:

Vanilla JS Reactive Engine 
// 1. Dependency Tracker
let activeEffect = null;

function createReactive(target) {
    const deps = new Map();

    return new Proxy(target, {
        get(obj, key) {
            // Track dependency
            if (activeEffect) {
                if (!deps.has(key)) deps.set(key, new Set());
                deps.get(key).add(activeEffect);
            }
            return obj[key];
        },
        set(obj, key, value) {
            obj[key] = value;
            // Trigger subscribers
            if (deps.has(key)) {
                deps.get(key).forEach(effect => effect());
            }
            return true;
        }
    });
}

function watchEffect(fn) {
    activeEffect = fn;
    fn(); // Jalankan pertama kali untuk merekam ketergantungan
    activeEffect = null;
}

// Penggunaan Nyata:
const state = createReactive({ harga: 50000, jumlah: 2 });

watchEffect(() => {
    // Otomatis dipanggil ulang setiap kali state.harga atau state.jumlah dimutasi!
    console.log('Total Belanja Terkalkulasi:', state.harga * state.jumlah);
});

// Mutasi state:
state.jumlah = 4; // Output: Total Belanja Terkalkulasi: 200000

7. Production War Stories & Anti-Patterns

War Story: Bencana Waterfall Hydration di Situs E-Commerce
Sebuah perusahaan marketplace menerapkan Server-Side Rendering (SSR) React penuh untuk halaman produk mereka. Meskipun HTML pertama kali muncul dengan cepat, pengguna di HP Android murah mengeluh bahwa tombol "Beli Sekarang" tidak bisa diklik selama 8 detik pertama!

Penyebab (The Hydration Trap): Browser menerima 1.8 MB bundle JavaScript React. Sebelum pengguna bisa berinteraksi, React harus mem-parse seluruh script, membangun ulang pohon Virtual DOM di client, dan mencocokkannya dengan HTML dari server (Full Page Hydration). Main thread CPU terkunci 100% (High Total Blocking Time - TBT).

Solusi: Mengadopsi Islands Architecture (Astro / Qwik). Bagian header, deskripsi produk, ulasan, dan footer disajikan sebagai Zero-JS HTML murni. Hanya tombol "Beli Sekarang" yang dimuat sebagai pulau JavaScript interaktif (~8KB), memangkas waktu TBT dari 8 detik menjadi 0.1 detik!

8. Kuis Uji Pemahaman: Paradigma Frontend Framework

1. Apa keunggulan mendasar Fine-Grained Signals (SolidJS/Vue/Angular) dibandingkan Virtual DOM diffing (React tradisional)?
A. Signals hanya dapat dieksekusi di server
B. Signals mengikat perubahan state langsung ke node DOM spesifik tanpa perlu menjalankan ulang fungsi komponen atau membandingkan seluruh pohon Virtual DOM
C. Signals menghasilkan Virtual DOM yang dua kali lebih besar
2. Dalam arsitektur Islands Architecture (seperti Astro), bagaimana cara kerja hidrasi JavaScript pada halaman web?
A. Seluruh halaman di-hidrasi secara serempak oleh satu bundel runtime monolitik
B. Mayoritas halaman tetap berupa HTML statis murni (Zero-JS), dan hanya komponen interaktif tertentu ('islands') yang diunduh dan di-hidrasi kodenya secara terisolasi
C. Mengharuskan aplikasi berjalan sepenuhnya di client tanpa SSR
