Modul 13: Monorepo vs Polyrepo (Multi-Repo Strategy)

Membedah strategi pengorganisasian repositori kode perangkat lunak: trade-off Polyrepo vs Monorepo, mitigasi Version Drift, mekanika Directed Acyclic Graph (DAG) Task Caching pada Turborepo dan Nx, serta studi kasus arsitektur skala Google dan Meta.

1. Skala Kode: Evolusi dari Startup Menuju Enterprise

Ketika sebuah perusahaan tumbuh, jumlah layanan bertambah dari 1 aplikasi monolit menjadi puluhan library bersama, aplikasi web, mobile, dan microservice. Pertanyaan mendasar yang menentukan produktivitas tim rekayasa adalah: Apakah seluruh kode tersebut harus disimpan di satu repositori (Monorepo) atau dipecah ke ratusan repositori terpisah (Polyrepo)?

2. Matriks Trade-off Komparatif

Dimensi Arsitektur Polyrepo (Multi-Repo) Monorepo Modern
Refactoring Lintas Layanan Sangat lambat. Memerlukan puluhan Pull Request terpisah, rilis versi semver ke private registry, dan koordinasi deployment antar tim. Atomic Refactoring: Ubah DTO bersama dan seluruh consumer (web, mobile, backend) di 1 Pull Request tunggal tanpa breaking changes!
Visibilitas & Discoverability Kode tersebar di ratusan repo. Sulit mencari siapa yang menggunakan fungsi tertentu. Pencarian Instan: Seluruh basis kode perusahaan berada di satu tempat yang mudah di-grep dan diaudit.
Waktu Eksekusi CI/CD Cepat di awal proyek, namun lambat secara agregat karena duplikasi pipeline. Terakselerasi dengan Task Graph Caching: Hanya paket yang berubah yang di-build dan diuji ulang.
Kontrol Akses & Ownership Mudah diatur via permission git level repositori. Memerlukan konfigurasi CODEOWNERS dan granular pull request approval gates.

3. Bahaya Version Drift & Dependency Hell di Polyrepo

Di arsitektur Polyrepo, tim membuat paket bersama seperti @perusahaan/design-system versi 1.0.0.

Skenario Dependency Drift
• Tim Checkout meng-upgrade design system ke versi 1.4.0.
• Tim Keranjang masih menggunakan versi 1.1.0.
• Tim Autentikasi masih terjebak di versi 0.8.0.

Hasilnya adalah pengalaman pengguna yang tidak konsisten (Visual Inconsistency) dan munculnya bug keamanan kritis yang lupa diperbarui oleh tim-tim tertentu. Di Monorepo, hanya ada SATU versi kanonikal tunggal (*Single Source of Truth*) untuk seluruh komponen bersama.

4. Task Graph & Remote Caching (Turborepo / Nx)

Bagaimana Monorepo sebesar Google (Piper) atau ribuan paket di Turborepo dapat mengeksekusi build dalam hitungan detik?

Mekanisme Directed Acyclic Graph (DAG)
1. Tooling membangun graf dependensi antar paket.
2. Tooling menghitung hash SHA-256 dari seluruh file input di dalam paket.
3. Jika hash cocok dengan cache di server cloud remote: Tooling langsung mengunduh hasil compile dist/ dan me-replay log terminal dalam waktu 200 milidetik (FULL TURBO CACHE HIT)!
4. Hanya paket yang filenya benar-benar diubah oleh developer yang akan dikompilasi ulang oleh CPU.

5. Kerangka Keputusan: Kapan Harus Memilih Monorepo?

  • Gunakan Monorepo Jika: Anda memiliki aplikasi web + backend + mobile yang saling berbagi tipe data (TypeScript DTO / Protobuf), tim bekerja secara kolaboratif, dan menginginkan kecepatan rilis fitur atomik.
  • Gunakan Polyrepo Jika: Layanan dibangun oleh tim pihak ketiga independen dengan siklus rilis yang sama sekali tidak berhubungan, atau ada regulasi hukum ketat yang melarang pengembang aplikasi A melihat kode aplikasi B.

6. Production War Stories & Anti-Patterns

War Story: Uber Migrasi 4.000 Polyrepo Menjadi Monorepo
Pada masa awal ekspansi cepat, Uber memiliki lebih dari 4.000 repositori microservice Git terpisah.

Ketika tim keamanan menemukan kerentanan kritis pada library logging HTTP bersama, mereka harus membuka 4.000 Pull Request terpisah dan menunggu ratusan tim menyetujui serta me-deploy-nya satu per satu. Proses perbaikan memakan waktu berbulan-bulan!

Uber kemudian memigrasikan basis kode Go mereka ke satu Monorepo raksasa terpadu. Ketika perbaikan keamanan dibutuhkan, mereka cukup mengubah 1 library bersama, menjalankan automated regression test di seluruh consumer, dan mem-push perbaikan secara serentak di hari yang sama!

7. Kuis Uji Pemahaman: Monorepo vs Polyrepo

1. Apa yang dimaksud dengan 'Atomic Refactoring' yang menjadi keunggulan utama arsitektur Monorepo?
A. Menulis ulang seluruh basis kode dari awal setiap sprint
B. Kemampuan mengubah skema data bersama dan seluruh aplikasi yang mengonsumsinya di dalam satu Pull Request/commit tunggal tanpa risiko breaking change
C. Menghapus git history agar repositori berukuran kecil
2. Bagaimana fitur Remote Caching pada Turborepo atau Nx mencegah build berulang di server CI?
A. Mengabaikan pengetesan unit test jika developer terburu-buru
B. Menghitung hash SHA dari file sumber dan konfigurasi; jika hash pernah dikompilasi sebelumnya, hasil build langsung diunduh dari cloud storage tanpa menjalankan compiler
C. Mematikan mesin CI agar menghemat tagihan cloud
