Modul 31: Arsitektur Mobile Runtimes, JSI, Fabric & Flutter Impeller

Membedah bagaimana kode aplikasi dieksekusi di perangkat keras seluler (smartphone): evolusi komunikasi antar-bahasa dari serialisasi JSON asinkronus (*Old Bridge*) ke pointer C++ langsung (*JSI & Fabric*), revolusi GPU renderer Flutter Impeller yang membasmi lag animasi iOS, kompilasi biner Kotlin Multiplatform, hingga manajemen memori perangkat keras (iOS ARC vs Android ART Garbage Collection).

1. Tiga Spektrum Arsitektur Mobile di Industri

Ketika membangun aplikasi mobile skala enterprise, software engineer dihadapkan pada tiga pendekatan arsitektur mendasar dengan karakteristik runtime yang sangat berbeda:

Paradigma Teknologi Mekanisme Rendering UI Kecepatan Eksekusi Logika Trade-off Utama
Murni Native Swift/SwiftUI (iOS)
Kotlin/Jetpack Compose (Android)		 Komponen widget native langsung dari OS (UIKit / Android View) Maksimal (Kompilasi LLVM / AOT mesin) Wajib menulis dua basis kode (*codebase*) terpisah untuk tim iOS dan Android.
Bridge / JSI Cross-Platform React Native (Meta) Komponen Native OS yang dikendalikan oleh engine JavaScript (Hermes) Sangat Cepat via pointer C++ (JSI & TurboModules) Membutuhkan integrasi binding C++ jika memanggil API native khusus yang belum didukung.
Owner-Drawn Canvas Engine Flutter (Google) Menggambar sendiri setiap piksel di atas canvas GPU via C++ Impeller / Metal / Vulkan Tinggi (Kompilasi Dart AOT ke binary ARM64) Ukuran file APK/IPA lebih besar (~15-30MB) karena menyertakan engine grafis sendiri di dalam aplikasi.

2. React Native Internals: Runtuhnya Old Bridge & Lahirnya JSI / Fabric

Selama hampir satu dekade, React Native dikritik karena masalah performa (*frame drop* saat scrolling cepat). Untuk memahami solusinya, kita wajib membedah apa yang terjadi di tingkat memori:

Arsitektur Lama: The JSON Bridge (Async Bottleneck)
• Pemisahan Ketat: Thread JavaScript (V8/JSC) dan Thread Native (Objective-C/Java) berada di semesta memori terpisah.
• Serialisasi JSON Lambat: Setiap sentuhan jari (Touch Event) diubah menjadi string JSON mentah JSON.stringify(), dilempar melintasi bridge asinkronus, lalu di-parse ulang di sisi JS.
• Masalah White Screen: Saat scrolling daftar 10.000 produk secara cepat, antrean pesan bridge penuh (*congested*), menyebabkan layar putih karena instruksi render tertunda.
New Architecture: JSI (JavaScript Interface) & Fabric
• Zero Serialization: JSI mengekspos objek C++ Host langsung ke runtime JavaScript (Hermes).
• Sinkronus & Instan: Kode JS dapat memegang referensi memori langsung ke fungsi native C++ tanpa melewati jembatan JSON.
• Fabric Renderer: Pembuatan pohon UI kini dihitung di thread background C++ menggunakan konsep immutable element trees, menjamin 60-120 FPS konstan.
Konsep Inti JSI (JavaScript Interface) dalam C++
Di bawah kap mesin JSI, JavaScript dapat memanggil fungsi C++ seolah-olah fungsi lokal: 
// Native C++ mengekspos pointer langsung ke JS Host Object
jsi::Value calculateDistance(jsi::Runtime& rt, const jsi::Value& thisVal, const jsi::Value* args, size_t count) {
    double lat = args[0].asNumber();
    double lon = args[1].asNumber();
    return jsi::Value(nativeHardwareGPS(lat, lon)); // Eksekusi 0ms tanpa JSON serialization!
}

3. Flutter Internals: Mengapa Skia Diganti Impeller?

Flutter tidak menggunakan widget bawaan iOS atau Android. Flutter membawa mesin grafisnya sendiri. Namun pengguna iOS generasi awal sering mengeluhkan Jank (patah-patah) saat animasi pertama kali dijalankan.

Masalah Lama: Skia Engine
Shader Compilation Jank
Skia mengompilasi shader grafis GPU (GLSL) secara Just-in-Time (JIT) di saat animasi sedang bergerak di layar. Kompilasi ini memakan waktu 30-80ms, melebihi anggaran frame 16.6ms sehingga animasi patah-patah.
Solusi Modern: Impeller Engine
Ahead-of-Time Pre-compiled Shaders
Impeller mengompilasi seluruh shader grafis GPU saat aplikasi di-build (AOT). Saat aplikasi dijalankan, GPU tinggal mengeksekusi pipeline Metal (iOS) atau Vulkan (Android) tanpa ada waktu henti kompilasi!

4. Kotlin Multiplatform (KMP): Berbagi Logika, Mempertahankan UI Native

Berbeda dengan Flutter dan React Native yang berusaha menyatukan logika dan UI, **Kotlin Multiplatform (KMP)** mengambil pendekatan pragmatis: "Share business logic, keep the UI native."

  • Di Android: Kode Kotlin bersama dikompilasi langsung menjadi bytecode JVM / Android DEX murni. Nol overhead performa.
  • Di iOS: Kompiler **Kotlin/Native (berbasis LLVM)** mengubah kode Kotlin bersama langsung menjadi binary statis berkas Framework Objective-C/Swift (Mach-O ARM64).
  • Lapisan UI: Tim iOS bebas mendesain menggunakan deklaratif **SwiftUI** murni, sementara tim Android menggunakan **Jetpack Compose** murni.

5. Memori Mobile: iOS ARC vs Android ART Garbage Collection

Salah satu penyebab terbesar perbedaan perilaku aplikasi di mobile adalah cara sistem operasi mengelola RAM:

iOS: Automatic Reference Counting (ARC)
• Deterministik Waktu Nyata: Setiap objek memiliki penghitung referensi (*reference counter*). Saat counter mencapai 0, memori seketika itu juga dibebaskan (nol pause).
• Bahaya Utama: Retain Cycles (dua objek saling memegang referensi strong). Wajib dipecahkan menggunakan pointer weak atau unowned.
Android: ART Generational Garbage Collection
• Asinkronus Tracing: Objek dialokasikan di Young Generation Heap. Garbage Collector (Concurrent Mark-Sweep) berjalan periodik membersihkan objek mati.
• Tantangan: Jika aplikasi mengalokasikan ribuan objek saat scrolling (misal parsing JSON di loop), GC memicu *GC pauses* yang menyebabkan *frame drop*.

6. Production War Story: Bottleneck Jembatan Serialisasi JSON

Bencana Kasus Nyata: Aplikasi Peta Finansial Drop dari 60 FPS ke 12 FPS

Sebuah aplikasi dompet digital menampilkan peta interaktif lokasi merchant terdekat di kota Jakarta. Setiap kali pengguna menggeser peta (*onRegionChange*), aplikasi mengirim koordinat lat/long ke sisi JavaScript untuk mencari 500 merchant terdekat, lalu mengirimkan array marker kembali ke sisi native iOS/Android.

Dampak yang Terjadi: Karena masih menggunakan arsitektur Old Bridge, setiap pergeseran jari 1 piksel memicu ratusan pesan JSON.stringify() dan JSON.parse() seberat 2MB melintasi jembatan thread. Thread bridge mengalami kemacetan total (*choke*). Tampilan peta membeku, animasi rute anjlok ke 12 FPS, dan HP pengguna menjadi sangat panas dalam 3 menit.

Solusi Arsitektur Baru: Tim memigrasikan modul peta ke React Native New Architecture (JSI / TurboModules). Alih-alih melempar string JSON melintasi jembatan, fungsi native C++ memanipulasi koordinat marker secara langsung di memori GPU shared pointer. Kemacetan JSON lenyap 100%, penggunaan CPU merosot 75%, dan peta kembali meluncur mulus di 60 FPS mentok!

7. Kuis Uji Pemahaman Arsitektur Mobile

1. Apa keunggulan teknis paling mendasar dari JSI (JavaScript Interface) pada arsitektur baru React Native dibanding arsitektur JSON Bridge lama?
A. JSI mengompresi payload JSON menggunakan format Protocol Buffers
B. JSI mengizinkan runtime JavaScript memegang referensi memori pointer langsung ke Host Object C++ tanpa serialisasi JSON string
C. JSI menghapus JavaScript dan menggantinya dengan kompilasi Java bytecode
2. Mengapa Google mengembangkan engine grafis Impeller untuk menggantikan Skia pada Flutter?
A. Mengeliminasi masalah Shader Compilation Jank di iOS dengan mengompilasi shader grafis GPU secara AOT (Ahead-of-Time) saat build
B. Menghilangkan ketergantungan pada API grafis Apple Metal
C. Mengubah kode Dart menjadi kode Kotlin secara otomatis
