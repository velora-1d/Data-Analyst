Modul 28: Site Reliability Engineering (SRE) & Resiliency Patterns

Filosofi ketahanan sistem terdistribusi skala internet: manajemen risiko berbasis Error Budget Google SRE, arsitektur pencegah kegagalan beruntun dengan Finite State Machine Circuit Breaker (Closed, Open, Half-Open), eliminasi badai retry via Exponential Backoff with Full Jitter, serta partisi isolasi Bulkhead.

Fondasi Konsep: Resiliensi Sistem & Circuit Breaker
Ibarat Sekring Listrik Otomatis di Rumah
Apa Ini Sebenarnya?

Pola pertahanan diri arsitektur software agar saat salah satu layanan mitra mogok, seluruh aplikasi Anda tidak ikut roboh terseret ke bawah.

Masalah Nyata Apa yang Diselesaikan?

Jika gateway pembayaran bank sedang eror selama 1 jam, jangan biarkan seluruh website toko online Anda ikut hang dan tidak bisa dibuka pengunjung lain!

Analogi Kehidupan Sehari-Hari

Ibarat sekring listrik di meteran rumah: saat terjadi korsleting di dapur, saklar sekring otomatis 'JEPRET' putus sendiri agar kabel di seluruh rumah tidak terbakar.

Kapan Kita Memakainya?

Wajib dipasang saat memanggil layanan pihak ketiga (Payment Gateway, API Kurir, Notifikasi SMS) yang bisa mogok sewaktu-waktu di luar kendali Anda.

1. Paradigma SRE: Kegagalan Adalah Keniscayaan

Di arsitektur cloud terdistribusi dengan ribuan mesin, server harddisk pasti rusak, kabel serat optik bawah laut pasti terputus, dan network partition pasti terjadi.

SRE (Site Reliability Engineering) yang dipelopori Google mengajarkan bahwa ketersediaan 100% adalah target yang salah: mengejar 100% menghabiskan biaya miliaran rupiah dan mematikan kecepatan rilis produk.

2. Hirarki SLI, SLO, SLA & Error Budget

Terminologi Definisi Baku Contoh Nyata
SLI (Indicator) Ukuran empiris kuantitatif kualitas layanan secara real-time Persentase request sukses HTTP 200 dalam 30 hari terakhir.
SLO (Objective) Target internal yang disepakati oleh tim engineering dan produk 99.9% request sukses dengan latensi < 200ms.
SLA (Agreement) Janji kontrak hukum kepada konsumen dengan penalti denda uang Jika uptime di bawah 99.5%, konsumen berhak refund 20% biaya langganan.
Error Budget Batas toleransi kegagalan yang diizinkan (100% - SLO) Pada SLO 99.9% per bulan, sistem diizinkan mengalami maksimal 43,8 menit downtime! Jika jatah ini habis, seluruh rilis fitur baru DIBEKUKAN sampai stabilitas pulih!

3. Circuit Breaker Pattern (Finite State Machine)

Seperti sekering listrik di rumah yang memutus arus saat korsleting agar kabel tidak terbakar, Circuit Breaker melindungi service hilir yang sedang sekarat:

Normal
CLOSED State
Semua request dialirkan normal ke service downstream. Kegagalan dihitung secara statistik.
Sekering Putus
OPEN State
Jika error > 50%, circuit TRIP! Semua request LANGSUNG DITOLAK seketika (Fail-Fast) tanpa menyentuh server hilir.
Uji Coba
HALF-OPEN State
Setelah masa jeda (misal 30 detik), 1-2 request percobaan diizinkan lewat. Jika sukses → CLOSED; jika gagal → OPEN kembali.

4. Bahaya Retry Storm & Solusi: Exponential Backoff with Full Jitter

Jika 10.000 klien gagal menghubungi server, dan semuanya melakukan retry bersamaan setiap 1 detik, server yang baru mulai pulih akan langsung tumbang seketika dihantam gelombang badai retry (Thundering Herd)!

Algoritma Full Jitter (AWS Architecture Whitepaper)
function calculateBackoffWithJitter(attempt, baseDelay = 100, maxDelay = 10000) {
    // 1. Hitung durasi eksponensial: 100ms, 200ms, 400ms, 800ms...
    const exponentialCap = Math.min(maxDelay, baseDelay * Math.pow(2, attempt));
    
    // 2. Terapkan Full Jitter acak acak antara 0 hingga exponentialCap!
    // Ini menyebarkan waktu retry jutaan klien secara merata di sepanjang sumbu waktu!
    return Math.floor(Math.random() * exponentialCap);
}

5. Bulkhead Pattern: Mencegah Kapal Tenggelam

Partisi Ruang Kedap Air (Bulkhead)
Pada kapal laut, lambung kapal dibagi menjadi sekat-sekat kedap air independen (Bulkhead) agar jika satu sekat bocor, seluruh kapal tidak ikut tenggelam.

Penerapan di Software:
Pisahkan Thread Pool / Connection Pool database! Jangan gunakan 1 pool bersama untuk API Pembayaran dan API Pencarian Katalog. Jika layanan pembayaran mitra pihak ketiga mendadak hang dan memakan 50 thread koneksi, pengguna masih tetap bisa mencari barang di katalog karena thread pencarian memiliki partisi mandiri!

6. Production War Stories & Anti-Patterns

War Story: Retry Loop Agresif Menghancurkan Kluster Database Utama
Sebuah bank digital mengalami gangguan jaringan sesaat selama 3 detik pada switch core data center.

Sebanyak 50 microservice yang kehilangan koneksi secara bersamaan mengeksekusi logika retry: while(error) { retry(); } tanpa backoff dan tanpa batas timeout!

Akibat: Ketika koneksi switch kembali online, kluster database PostgreSQL utama dihujani 250.000 koneksi serentak per detik. CPU database seketika terkunci di 100% dan seluruh sistem perbankan lumpuh total selama 4 jam!

Pencegahan: Setiap panggilan keluar WAJIB memiliki Circuit Breaker, timeout maksimal 3 detik, dan algoritma Exponential Backoff dengan Full Jitter!
