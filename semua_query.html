Belajar Semua Query SQL: Katalog 30 Perintah Industri

Pelajari anatomi query basis data relasional mulai dari tingkat dasar hingga analitik lanjutan. Setiap contoh dilengkapi penjelasan konkret "Query ini untuk apa?", skenario penggunaan di dunia kerja nyata, dan bagaimana database engine memprosesnya.

Kategori 1: Query Dasar & Pemilihan Kolom

5 Contoh Perintah
1.1
Memilih Kolom Spesifik & Pembatasan Baris Data
SELECT & LIMIT
Query ini untuk apa?
Digunakan untuk menarik sampel katalog nama produk dan berat fisiknya tanpa menyedot seluruh tabel. Hal ini sangat penting untuk mencegah pemborosan RAM server (*overfetching*) saat sistem hanya membutuhkan data tertentu untuk perhitungan berat paket pengiriman.
Kapan digunakan? Saat backend API membuat endpoint ringkas katalog produk atau tim logistik mengecek berat rata-rata barang untuk pengemasan.
SELECT 
    nama_produk, 
    berat_gram
FROM produk
LIMIT 5;
Cara kerjanya:
  • SELECT nama_produk, berat_gram: Database engine hanya membaca 2 kolom dari disk penyimpanan.
  • LIMIT 5: Menghentikan eksekusi pemindaian (*cursor scan*) tepat setelah baris ke-5 ditemukan.
1.2
Memberi Alias Kolom & Kalkulasi Margin Keuntungan
AS & Aritmatika
Query ini untuk apa?
Digunakan untuk menghitung estimasi keuntungan kotor (margin rupiah) per unit produk secara langsung pada tingkat database tanpa perlu memproses pengurangan harga di bahasa pemrograman frontend/backend.
Kapan digunakan? Di dashboard keuangan manajemen toko ketika finance manager mengecek produk mana yang memberikan sumbangan laba nominal terbesar.
SELECT 
    sku,
    harga_modal,
    harga_jual,
    (harga_jual - harga_modal) AS keuntungan_nominal
FROM variasi_produk
LIMIT 5;
Cara kerjanya:
  • Ekspresi (harga_jual - harga_modal) menghitung selisih harga secara on-the-fly per baris.
  • Kata kunci AS keuntungan_nominal memberi label nama kolom baru di struktur response query.
1.3
Menghilangkan Duplikasi Baris Wilayah Pengiriman
DISTINCT & ORDER BY
Query ini untuk apa?
Digunakan untuk mengekstrak daftar unik nama provinsi dan kota tujuan pesanan yang pernah dilayani, sehingga tidak ada nama kota yang muncul berulang-ulang meskipun terdapat ribuan pelanggan di kota tersebut.
Kapan digunakan? Untuk mengisi dropdown wilayah pengiriman pada form checkout atau analisis jangkauan coverage ekspedisi kurir.
SELECT DISTINCT 
    kota, 
    provinsi
FROM alamat_pelanggan
ORDER BY provinsi ASC, kota ASC
LIMIT 5;
Cara kerjanya:
  • DISTINCT mengeliminasi rekaman duplikat pada kombinasi pasangan nilai kota dan provinsi.
  • ORDER BY provinsi ASC, kota ASC menata urutan alfabetis dari provinsi lalu ke tingkat kota.
1.4
Paginasi Halaman Data Transaksi (Pagination)
LIMIT & OFFSET
Query ini untuk apa?
Digunakan untuk membagi ribuan transaksi ke dalam halaman-halaman antarmuka aplikasi. Contoh di bawah mengambil data untuk Halaman ke-2 dengan ukuran 5 baris per halaman (melewatkan 5 data teratas pertama).
Kapan digunakan? Pada REST API endpoint table dashboard admin (misal /api/orders?page=2&limit=5).
SELECT 
    nomor_invoice, 
    tanggal_pesanan, 
    total_bayar
FROM pesanan
ORDER BY total_bayar DESC
LIMIT 5 OFFSET 5;
Cara kerjanya:
  • LIMIT 5: Mengambil maksimum 5 rekaman.
  • OFFSET 5: Melompati 5 baris hasil teratas (peringkat 1 s/d 5) dan mengembalikan peringkat 6 s/d 10.
1.5
Penanganan Nilai Kosong Diskon (COALESCE)
COALESCE & NULL Handling
Query ini untuk apa?
Digunakan untuk mengamankan data transaksi yang tidak menggunakan kupon voucher (`voucher_id` bernilai `NULL`). Fungsi `COALESCE` mengganti nilai `NULL` menjadi angka default `0` agar aman saat dikonsumsi oleh aplikasi klien.
Kapan digunakan? Saat proses ekspor data invoice ke sistem pelaporan pajak/akuntansi agar tidak menimbulkan kegagalan *NullPointerException*.
SELECT 
    nomor_invoice,
    COALESCE(voucher_id, 0) AS voucher_id_bersih,
    potongan_diskon,
    total_bayar
FROM pesanan
LIMIT 5;
Cara kerjanya:
  • COALESCE(voucher_id, 0): Mengevaluasi nilai voucher_id; jika bernilai NULL, maka angka 0 yang akan dikembalikan.

Kategori 2: Filtering & Pencarian Spesifik

5 Contoh Perintah
2.1
Filter Transaksi Selesai Bernilai Tinggi (WHERE & AND)
WHERE & Operator >=
Query ini untuk apa?
Digunakan untuk mengaudit transaksi sukses dengan nilai pembayaran di atas Rp 1.000.000 guna memastikan seluruh pesanan bernilai jumbo telah selesai diproses tanpa kendala retur atau keluhan pelanggan.
Kapan digunakan? Saat tim rekonsiliasi keuangan memverifikasi transfer dana masuk bernilai tinggi dari payment gateway ke rekening bank perusahaan.
SELECT 
    nomor_invoice, 
    tanggal_pesanan, 
    total_bayar, 
    status_pesanan
FROM pesanan
WHERE status_pesanan = 'Selesai' 
  AND total_bayar >= 1000000
ORDER BY total_bayar DESC 
LIMIT 5;
Cara kerjanya:
  • Klausa WHERE menyaring baris sebelum diurutkan. Operator AND mewajibkan kedua kriteria bernilai benar (TRUE).
2.2
Filter Berdasarkan Kumpulan Status Antrean (Operator IN)
Operator IN
Query ini untuk apa?
Digunakan oleh tim gudang dan logistik untuk memantau seluruh antrean paket yang statusnya sedang 'Diproses' atau sedang 'Dikirim' agar tidak ada pesanan tertinggal (*order backlog*).
Kapan digunakan? Pada layar monitor fulfillment gudang pusat yang me-refresh status pesanan yang masih berjalan secara real-time.
SELECT 
    nomor_invoice, 
    tanggal_pesanan, 
    status_pesanan, 
    total_bayar
FROM pesanan
WHERE status_pesanan IN ('Diproses', 'Dikirim')
ORDER BY tanggal_pesanan DESC
LIMIT 5;
Cara kerjanya:
  • status_pesanan IN ('Diproses', 'Dikirim') mencocokkan baris mana pun yang nilainya ada di dalam set daftar yang diberikan.
2.3
Filter Rentang Nilai Belanja Menengah (Operator BETWEEN)
Operator BETWEEN
Query ini untuk apa?
Digunakan untuk menganalisis pesanan yang berada pada rentang nilai belanja menengah (antara Rp 250.000 hingga Rp 500.000), yaitu target segmen konsumen paling dominan di platform e-commerce.
Kapan digunakan? Saat tim growth marketing merancang syarat batas minimum belanja untuk mendapatkan gratis ongkir spesial.
SELECT 
    nomor_invoice, 
    total_bayar, 
    status_pesanan
FROM pesanan
WHERE total_bayar BETWEEN 250000 AND 500000
ORDER BY total_bayar DESC
LIMIT 5;
Cara kerjanya:
  • BETWEEN 250000 AND 500000 bersifat inklusif, menyaring angka dari 250 ribu hingga 500 ribu secara ringkas dan efisien.
2.4
Pencarian Pola Kata Kunci Produk (LIKE & Wildcard)
LIKE & Wildcard %
Query ini untuk apa?
Digunakan untuk mendukung fitur kotak pencarian (*search bar*) toko online yang mencari barang berdasarkan substring kata kunci seperti perangkat 'Wireless' atau perlengkapan 'Gaming'.
Kapan digunakan? Pada endpoint search API katalog ketika pembeli mengetik kata kunci bebas di search bar website.
SELECT 
    produk_id, 
    nama_produk, 
    deskripsi
FROM produk
WHERE nama_produk LIKE '%Wireless%' 
   OR nama_produk LIKE '%Gaming%'
LIMIT 5;
Cara kerjanya:
  • Simbol % adalah wildcard yang mencocokkan sembarang karakter di awal maupun di akhir kata kunci yang dicari.
2.5
Deteksi Transaksi Organik Tanpa Voucher (IS NULL)
IS NULL
Query ini untuk apa?
Digunakan untuk mengukur kesehatan transaksi alami toko: transaksi mana saja yang dibuat oleh pembeli tanpa menggunakan kode voucher diskon sama sekali (`voucher_id IS NULL`).
Kapan digunakan? Saat manajemen menghitung seberapa besar ketergantungan toko terhadap subsidi diskon promosi (*organic conversion rate*).
SELECT 
    nomor_invoice, 
    potongan_diskon, 
    voucher_id, 
    total_bayar, 
    tanggal_pesanan
FROM pesanan
WHERE voucher_id IS NULL
ORDER BY tanggal_pesanan DESC
LIMIT 5;
Cara kerjanya:
  • Standar SQL mewajibkan sintaks IS NULL karena nilai NULL menandakan ketiadaan nilai (*unknown*), bukan angka nol atau teks kosong.

Kategori 3: Agregasi & Metrik Bisnis

5 Contoh Perintah
3.1
Menghitung Total Transaksi & Omzet Kotor Penjualan
COUNT & SUM
Query ini untuk apa?
Digunakan untuk menghitung dua Key Performance Indicator (KPI) paling krusial di e-commerce: total volume transaksi sukses dan total uang masuk kotor (*Gross Revenue*).
Kapan digunakan? Ditampilkan di kartu ringkasan eksekutif (*Executive Summary Card*) di pojok atas dashboard pemilik bisnis.
SELECT 
    COUNT(*) AS total_transaksi_selesai,
    SUM(total_bayar) AS total_omzet_kotor
FROM pesanan
WHERE status_pesanan = 'Selesai';
Cara kerjanya:
  • COUNT(*) menghitung seluruh jumlah baris transaksi sukses.
  • SUM(total_bayar) menjumlahkan akumulasi nilai uang dari seluruh transaksi tersebut.
3.2
Menghitung Rata-rata Nilai Belanja Pesanan (AOV)
AVG & ROUND
Query ini untuk apa?
Digunakan untuk menghitung *Average Order Value (AOV)*, yaitu rata-rata rupiah yang dihabiskan seorang pembeli setiap kali membuat pesanan di toko online.
Kapan digunakan? Saat tim produk mengevaluasi efektivitas rekomendasi paket *bundling* atau *cross-selling* barang tambahan di keranjang belanja.
SELECT 
    COUNT(DISTINCT pelanggan_id) AS total_pembeli_aktif,
    ROUND(AVG(total_bayar), 0) AS rata_rata_belanja_aov
FROM pesanan
WHERE status_pesanan = 'Selesai';
Cara kerjanya:
  • AVG(total_bayar) menghitung nilai rata-rata aritmatika seluruh transaksi selesai.
  • ROUND(..., 0) membulatkan nilai desimal ke bilangan bulat rupiah terdekat.
3.3
Rekap Pendapatan per Metode Pembayaran (GROUP BY)
GROUP BY & JOIN
Query ini untuk apa?
Digunakan untuk mengelompokkan omzet berdasarkan kanal pembayaran (QRIS, Kartu Kredit, Virtual Account, COD, dll.) guna mengetahui saluran transaksi favorit pelanggan.
Kapan digunakan? Saat negosiasi persentase biaya transaksi (*MDR Fee*) dengan payment gateway vendor.
SELECT 
    mp.nama_metode,
    COUNT(p.pesanan_id) AS jumlah_transaksi,
    SUM(p.total_bayar) AS total_pendapatan
FROM pesanan p
JOIN metode_pembayaran mp ON p.metode_id = mp.metode_id
WHERE p.status_pesanan = 'Selesai'
GROUP BY mp.nama_metode
ORDER BY total_pendapatan DESC;
Cara kerjanya:
  • Klausa GROUP BY mp.nama_metode memisahkan baris pesanan ke dalam kelompok kategori pembayaran sebelum fungsi agregasi dihitung.
3.4
Tren Omzet Bulanan Toko (STRFTIME & GROUP BY)
STRFTIME & Tren Waktu
Query ini untuk apa?
Digunakan untuk mengekstrak tahun-bulan (`YYYY-MM`) dari tanggal transaksi dan merekap pertumbuhan omzet dari bulan ke bulan guna melihat pola musiman (*seasonality*).
Kapan digunakan? Sebagai sumber data grafik batang (*Bar Chart*) bulanan pada laporan keuangan bulanan direksi.
SELECT 
    STRFTIME('%Y-%m', tanggal_pesanan) AS periode_bulan,
    COUNT(*) AS jumlah_pesanan,
    SUM(total_bayar) AS omzet_bulanan
FROM pesanan
WHERE status_pesanan = 'Selesai'
GROUP BY periode_bulan
ORDER BY periode_bulan ASC
LIMIT 6;
Cara kerjanya:
  • STRFTIME('%Y-%m', tanggal_pesanan) mengabaikan hari dan jam, menyisakan format tahun dan bulan sebagai kunci pengelompokan.
3.5
Menyaring Kelompok Kategori Beromzet Tinggi (HAVING)
HAVING & Threshold
Query ini untuk apa?
Digunakan untuk memfilter hasil grup agregasi: hanya menampilkan kategori produk yang total omzet penjualannya mencapai ambang batas target (di atas Rp 50.000.000).
Kapan digunakan? Saat rapat strategi bisnis untuk memisahkan kategori unggulan (*star categories*) dari kategori yang penjualannya lambat.
SELECT 
    k.nama_kategori,
    SUM(rp.subtotal) AS total_omzet
FROM rincian_pesanan rp
JOIN variasi_produk vp ON rp.variasi_id = vp.variasi_id
JOIN produk pr ON vp.produk_id = pr.produk_id
JOIN subkategori sk ON pr.subkategori_id = sk.subkategori_id
JOIN kategori k ON sk.kategori_id = k.kategori_id
GROUP BY k.nama_kategori
HAVING total_omzet >= 50000000
ORDER BY total_omzet DESC;
Cara kerjanya:
  • HAVING menyaring baris *setelah* agregasi terjadi, berbeda dengan WHERE yang menyaring baris sebelum dihitung totalnya.

Kategori 4: Relasi Multi-Tabel & JOIN

5 Contoh Perintah
4.1
Menghubungkan Transaksi dengan Profil Pelanggan (INNER JOIN)
INNER JOIN Dasar
Query ini untuk apa?
Digunakan untuk menampilkan nomor invoice pesanan lengkap bersama identitas asli orang yang membelinya (nama lengkap, email, nomor HP) dari tabel terpisah `pelanggan`.
Kapan digunakan? Saat Customer Support mencari riwayat pemilik pesanan ketika ada komplain pembayaran.
SELECT 
    p.nomor_invoice,
    pel.nama_lengkap,
    pel.email,
    p.total_bayar,
    p.status_pesanan
FROM pesanan p
INNER JOIN pelanggan pel ON p.pelanggan_id = pel.pelanggan_id
LIMIT 5;
Cara kerjanya:
  • Klausa INNER JOIN mencocokkan foreign key p.pelanggan_id dengan primary key pel.pelanggan_id.
4.2
Mencetak Rincian Struk Faktur Belanja Lengkap (Multi-JOIN)
Multi-Table JOIN
Query ini untuk apa?
Digunakan untuk mengumpulkan seluruh komponen struk belanja fisik: dari nomor invoice, nama produk, spesifikasi warna/ukuran varian, jumlah beli, hingga subtotal harga per baris.
Kapan digunakan? Saat sistem mencetak surat jalan atau invoice PDF yang dimasukkan ke dalam paket pengiriman barang.
SELECT 
    p.nomor_invoice,
    pr.nama_produk,
    vp.warna,
    vp.ukuran,
    rp.jumlah,
    rp.harga_satuan,
    rp.subtotal
FROM pesanan p
INNER JOIN rincian_pesanan rp ON p.pesanan_id = rp.pesanan_id
INNER JOIN variasi_produk vp ON rp.variasi_id = vp.variasi_id
INNER JOIN produk pr ON vp.produk_id = pr.produk_id
LIMIT 5;
Cara kerjanya:
  • Menggabungkan 4 tabel sekaligus secara berantai: Pesanan → Rincian → Varian SKU → Katalog Induk Produk.
4.3
Melacak Kurir Ekspedisi & Nomor Resi Pengiriman
Relasi Logistik
Query ini untuk apa?
Digunakan untuk memonitor progres pengiriman logistik: menggabungkan pesanan dengan partner kurir pengangkut (JNE, SiCepat, dll.) dan nomor resi pelacakan aktif.
Kapan digunakan? Ditampilkan pada halaman pelacakan pesanan pembeli (*Order Tracking Screen*) di aplikasi seluler toko.
SELECT 
    p.nomor_invoice,
    k.nama_kurir,
    k.layanan,
    sp.status_pengiriman,
    sp.nomor_resi
FROM pesanan p
INNER JOIN kurir_ekspedisi k ON p.kurir_id = k.kurir_id
INNER JOIN status_pengiriman sp ON p.pesanan_id = sp.pesanan_id
LIMIT 5;
Cara kerjanya:
  • Menghubungkan entitas transaksi dengan status logistik kurir eksternal secara terintegrasi.
4.4
Menemukan Pelanggan Terdaftar yang Belum Pernah Belanja
LEFT JOIN & IS NULL
Query ini untuk apa?
Digunakan untuk mendeteksi akun pelanggan yang sudah mendaftar tetapi belum pernah menyelesaikan satu transaksi pun, guna mencari user pasif untuk program reaktivasi.
Kapan digunakan? Tim CRM marketing menggunakan data ini untuk mengirimkan voucher selamat datang (*First-order Incentive*).
SELECT 
    pel.pelanggan_id,
    pel.nama_lengkap,
    pel.email,
    pel.tanggal_daftar
FROM pelanggan pel
LEFT JOIN pesanan p ON pel.pelanggan_id = p.pelanggan_id
WHERE p.pesanan_id IS NULL
LIMIT 5;
Cara kerjanya:
  • LEFT JOIN mempertahankan seluruh data pelanggan di sisi kiri, dan kondisi WHERE p.pesanan_id IS NULL menyaring akun yang tidak punya relasi transaksi.
4.5
Memantau Stok Menipis per Lokasi Gudang Fisik
Inventaris Multi-Gudang
Query ini untuk apa?
Digunakan untuk mendeteksi barang-barang yang stoknya kritis (tersisa 10 unit atau kurang) beserta informasi di gudang kota mana barang tersebut disimpan.
Kapan digunakan? Di sistem procurement gudang untuk memicu Purchase Order otomatis ke supplier (*Low Stock Alert*).
SELECT 
    pr.nama_produk,
    vp.sku,
    g.nama_gudang,
    g.kota,
    sg.stok_tersedia
FROM stok_gudang sg
INNER JOIN gudang g ON sg.gudang_id = g.gudang_id
INNER JOIN variasi_produk vp ON sg.variasi_id = vp.variasi_id
INNER JOIN produk pr ON vp.produk_id = pr.produk_id
WHERE sg.stok_tersedia <= 10
ORDER BY sg.stok_tersedia ASC
LIMIT 5;
Cara kerjanya:
  • Menghubungkan tabel persediaan fisik stok_gudang dengan master gudang dan katalog SKU barang.

Kategori 5: Subquery & Common Table Expressions (CTE)

5 Contoh Perintah
5.1
Mencari Pesanan di Atas Rata-rata Toko (Scalar Subquery)
Scalar Subquery
Query ini untuk apa?
Digunakan untuk memfilter pesanan yang nominal belanjanya secara dinamis lebih tinggi daripada rata-rata belanja seluruh transaksi toko tanpa perlu menghitung angka rata-rata secara manual di luar query.
Kapan digunakan? Saat analis mengidentifikasi transaksi pembeli berkantong tebal (*High Spender Segment*).
SELECT 
    nomor_invoice, 
    total_bayar, 
    tanggal_pesanan
FROM pesanan
WHERE total_bayar > (
    SELECT AVG(total_bayar) 
    FROM pesanan 
    WHERE status_pesanan = 'Selesai'
)
ORDER BY total_bayar DESC
LIMIT 5;
Cara kerjanya:
  • Subquery di dalam kurung dieksekusi terlebih dahulu menghasilkan 1 angka rata-rata, lalu angka tersebut dijadikan batas pembanding klausa WHERE luar.
5.2
Menyaring Pelanggan Pembeli Kategori Khusus (Subquery IN)
Subquery di Klausa IN
Query ini untuk apa?
Digunakan untuk memfilter profil pelanggan yang pernah membeli produk dari kategori induk tertentu (misal Kategori ID = 1 / Elektronik) untuk sasaran promosi bertarget.
Kapan digunakan? Saat tim pemasaran ingin meluncurkan promo gadget terbaru hanya kepada user yang punya minat belanja barang elektronik.
SELECT 
    pel.nama_lengkap, 
    pel.email
FROM pelanggan pel
WHERE pel.pelanggan_id IN (
    SELECT DISTINCT p.pelanggan_id
    FROM pesanan p
    JOIN rincian_pesanan rp ON p.pesanan_id = rp.pesanan_id
    JOIN variasi_produk vp ON rp.variasi_id = vp.variasi_id
    JOIN produk pr ON vp.produk_id = pr.produk_id
    JOIN subkategori sk ON pr.subkategori_id = sk.subkategori_id
    WHERE sk.kategori_id = 1
)
LIMIT 5;
Cara kerjanya:
  • Subquery menghasilkan daftar array ID pelanggan yang memenuhi kriteria, lalu query utama mengambil identitas nama & email mereka.
5.3
Menghitung Rata-rata Frekuensi Belanja per User (Derived Table)
Derived Table (FROM Subquery)
Query ini untuk apa?
Digunakan untuk menghitung rata-rata dari hasil agregasi tingkat pertama: seberapa sering seorang pelanggan berbelanja di toko kita selama hidupnya (*Purchase Frequency*).
Kapan digunakan? Untuk metrik Customer Lifetime Value (CLV) dan analisis loyalitas pelanggan.
SELECT 
    ROUND(AVG(transaksi_per_user), 1) AS rata_rata_pesanan_per_user
FROM (
    SELECT 
        pelanggan_id, 
        COUNT(*) AS transaksi_per_user
    FROM pesanan
    GROUP BY pelanggan_id
);
Cara kerjanya:
  • Subquery di dalam klausa FROM membentuk tabel virtual sementara yang kemudian dihitung rata-ratanya oleh query luar.
5.4
Membuat Alur Analisis Bersih Modular (Single CTE)
WITH CTE
Query ini untuk apa?
Digunakan untuk menstrukturkan query kompleks agar mudah dibaca seperti membaca paragraf kode pemrograman biasa, dengan mendefinisikan tabel sementara bernama `pesanan_sukses` di awal.
Kapan digunakan? Praktik terbaik arsitektur data SQL (*Clean Code Data Pipeline*) agar query analitik mudah di-maintain dan di-review rekan kerja.
WITH pesanan_sukses AS (
    SELECT 
        pesanan_id, 
        nomor_invoice, 
        pelanggan_id, 
        total_bayar
    FROM pesanan
    WHERE status_pesanan = 'Selesai'
)
SELECT 
    ps.nomor_invoice,
    pel.nama_lengkap,
    ps.total_bayar
FROM pesanan_sukses ps
JOIN pelanggan pel ON ps.pelanggan_id = pel.pelanggan_id
ORDER BY ps.total_bayar DESC
LIMIT 5;
Cara kerjanya:
  • Blok WITH pesanan_sukses AS (...) mengisolasi proses filtering terlebih dahulu, membuat query gabungan di bawahnya jauh lebih rapi.
5.5
Komparasi Omzet Kotor & Beban Diskon (Multi-CTE)
Multi-CTE Analitik
Query ini untuk apa?
Digunakan untuk menghitung pendapatan bersih (*Net Revenue*) dengan cara menyusun dua blok kalkulasi independen: total omzet kotor dan total biaya subsidi diskon promo yang dikeluarkan toko.
Kapan digunakan? Saat evaluasi profitabilitas promosi oleh tim finance dan CEO dalam menghitung return on investment kampanye diskon.
WITH rekap_omzet AS (
    SELECT SUM(total_bayar) AS gross_revenue
    FROM pesanan
    WHERE status_pesanan = 'Selesai'
),
rekap_diskon AS (
    SELECT SUM(potongan_diskon) AS total_bakar_uang
    FROM pesanan
    WHERE status_pesanan = 'Selesai'
)
SELECT 
    ro.gross_revenue,
    rd.total_bakar_uang,
    (ro.gross_revenue - rd.total_bakar_uang) AS net_revenue
FROM rekap_omzet ro, rekap_diskon rd;
Cara kerjanya:
  • Membuat beberapa CTE sekaligus yang dipisahkan tanda koma, lalu menggabungkannya dalam satu laporan baris akhir.

Kategori 6: Window Functions & Analisis Tren

5 Contoh Perintah
6.1
Menomori Urutan Belanja Historis User (ROW_NUMBER)
ROW_NUMBER() OVER
Query ini untuk apa?
Digunakan untuk menomori secara kronologis setiap transaksi yang dilakukan oleh masing-masing pelanggan (transaksi ke-1, ke-2, ke-3, dst.) guna membedakan pembelian perdana dari pembelian berulang (*repeat order*).
Kapan digunakan? Saat menghitung metrik retensi dan cohort analisis perilaku pembeli di platform online.
SELECT 
    pelanggan_id,
    nomor_invoice,
    tanggal_pesanan,
    ROW_NUMBER() OVER(
        PARTITION BY pelanggan_id 
        ORDER BY tanggal_pesanan ASC
    ) AS urutan_transaksi_ke
FROM pesanan
LIMIT 6;
Cara kerjanya:
  • PARTITION BY pelanggan_id memisahkan nomor urut per user, dan urutan di-reset kembali ke angka 1 setiap kali berganti pelanggan.
6.2
Menentukan Ranking Produk Terlaris (DENSE_RANK)
DENSE_RANK() OVER
Query ini untuk apa?
Digunakan untuk menentukan peringkat produk paling laku berdasarkan total kuantitas terjual tanpa ada nomor ranking yang terlewat jika terjadi jumlah penjualan yang seri.
Kapan digunakan? Menampilkan badge *"Produk Terlaris #1, #2, #3"* pada halaman etalase toko online.
SELECT 
    pr.nama_produk,
    SUM(rp.jumlah) AS total_terjual,
    DENSE_RANK() OVER(
        ORDER BY SUM(rp.jumlah) DESC
    ) AS ranking_terlaris
FROM rincian_pesanan rp
JOIN variasi_produk vp ON rp.variasi_id = vp.variasi_id
JOIN produk pr ON vp.produk_id = pr.produk_id
GROUP BY pr.produk_id
LIMIT 5;
Cara kerjanya:
  • DENSE_RANK() mengurutkan produk dari jumlah terjual terbanyak dan memberikan peringkat berurutan 1, 2, 3 tanpa celah.
6.3
Menghitung Akumulasi Omzet Berjalan (Running Total)
Running Total (SUM OVER)
Query ini untuk apa?
Digunakan untuk melihat total uang masuk kumulatif dari hari ke hari (penjualan hari ini ditambahkan dengan seluruh penjualan hari-hari sebelumnya) sepanjang tahun.
Kapan digunakan? Untuk memplot grafik garis kumulatif kas perusahaan menuju pencapaian target tahunan (*Year-to-Date Revenue pacing*).
SELECT 
    DATE(tanggal_pesanan) AS tanggal,
    SUM(total_bayar) AS omzet_harian,
    SUM(SUM(total_bayar)) OVER(
        ORDER BY DATE(tanggal_pesanan) ASC
    ) AS running_total_omzet
FROM pesanan
WHERE status_pesanan = 'Selesai'
GROUP BY DATE(tanggal_pesanan)
LIMIT 5;
Cara kerjanya:
  • SUM(...) OVER(ORDER BY tanggal ASC) menjumlahkan nilai baris demi baris secara progresif dari rekaman paling awal.
6.4
Membandingkan Omzet dengan Bulan Sebelumnya (LAG)
LAG() OVER (MoM Growth)
Query ini untuk apa?
Digunakan untuk menarik nilai omzet dari 1 baris sebelumnya secara langsung ke baris saat ini, sehingga kita bisa menghitung selisih pertumbuhan penjualan dari bulan lalu (*Month-over-Month*).
Kapan digunakan? Saat rapat evaluasi bulanan tim growth untuk melihat persentase kenaikan atau penurunan omzet toko.
SELECT 
    STRFTIME('%Y-%m', tanggal_pesanan) AS bulan,
    SUM(total_bayar) AS omzet_bulan_ini,
    LAG(SUM(total_bayar), 1) OVER(
        ORDER BY STRFTIME('%Y-%m', tanggal_pesanan) ASC
    ) AS omzet_bulan_lalu
FROM pesanan
WHERE status_pesanan = 'Selesai'
GROUP BY bulan
LIMIT 5;
Cara kerjanya:
  • LAG(..., 1) mengintip dan mengambil data tepat 1 baris di atas baris yang sedang aktif.
6.5
Menghitung Porsi Persentase Terhadap Induk Kategori
SUM() OVER PARTITION BY
Query ini untuk apa?
Digunakan untuk menghitung berapa persen sumbangan omzet satu produk tertentu terhadap total omzet seluruh kategori induknya (analisis pareto produk).
Kapan digunakan? Saat merencanakan strategi alokasi anggaran iklan promosi agar terfokus pada produk penyumbang 80% omzet kategori.
SELECT 
    k.nama_kategori,
    pr.nama_produk,
    SUM(rp.subtotal) AS omzet_produk,
    ROUND(
        SUM(rp.subtotal) * 100.0 / 
        SUM(SUM(rp.subtotal)) OVER(PARTITION BY k.kategori_id), 
        2
    ) AS persen_kontribusi_kategori
FROM rincian_pesanan rp
JOIN variasi_produk vp ON rp.variasi_id = vp.variasi_id
JOIN produk pr ON vp.produk_id = pr.produk_id
JOIN subkategori sk ON pr.subkategori_id = sk.subkategori_id
JOIN kategori k ON sk.kategori_id = k.kategori_id
GROUP BY pr.produk_id
LIMIT 5;
Cara kerjanya:
  • Penyebut rumus menggunakan OVER(PARTITION BY k.kategori_id) yang secara otomatis menghitung total omzet satu kategori tanpa merusak detail baris produk.
