Fungsi Agregasi & Metrik Penjualan Bisnis

Agregasi adalah inti dari Business Intelligence. Di modul ini Anda akan belajar cara menghitung GMV (Gross Merchandise Value), AOV (Average Order Value), volume pesanan harian, dan segmentasi omzet per metode pembayaran dan wilayah.

1. Pengantar Fungsi Agregasi

Fungsi agregasi mengambil sekumpulan nilai baris dan merangkumnya menjadi satu nilai statistik ringkasan. Fungsi agregasi mengabaikan nilai NULL (kecuali COUNT(*)).

Buat Apa Fungsi Agregasi Diciptakan?

Tanpa fungsi agregasi, Anda harus membaca ratusan ribu baris data transaksi satu per satu secara manual. Dengan Agregasi SQL, database SQLite secara instan menghitung total nilai transaksi (GMV), rata-rata belanja per invoice (AOV), serta batas nilai transaksi tertinggi dan terendah dalam hitungan milidetik.

2. COUNT(*) vs COUNT(kolom)

COUNT(*) menghitung seluruh baris fisik di tabel. Sedangkan COUNT(kolom) hanya menghitung baris yang kolomnya tidak bernilai NULL.

Skenario Analisis Bisnis: Penetrasi Promo Voucher

Tim Marketing ingin mengetahui efektivitas promo voucher. Karena voucher_id bernilai NULL jika pelanggan belanja tanpa voucher, kita bisa membandingkan COUNT(*) (seluruh order) dengan COUNT(voucher_id) (order yang memakai voucher) untuk menghitung persentase penggunaan voucher.

SQL Query
-- Rekapitulasi pesanan dan pemakaian voucher diskon
SELECT 
    COUNT(*)                                 AS total_seluruh_pesanan,
    COUNT(voucher_id)                        AS pesanan_pakai_voucher,
    COUNT(*) - COUNT(voucher_id)              AS pesanan_tanpa_voucher
FROM pesanan;

3. SUM & AVG: Total Omzet & Average Order Value (AOV)

Kapan SUM & AVG Digunakan?
  • SUM(total_bayar): Digunakan saat Direktur Keuangan meminta total pendapatan kotor (Gross Sales).
  • AVG(total_bayar): Digunakan oleh Tim Product untuk mengukur daya beli rata-rata pengguna (Average Order Value / AOV). Jika AOV naik dari Rp 150.000 menjadi Rp 250.000, berarti strategi upselling produk berhasil.
SQL Query
-- Ringkasan omzet dan AOV pesanan dengan status 'Selesai'
SELECT 
    COUNT(*)                     AS total_pesanan_sukses,
    SUM(total_bayar)             AS total_omzet_kotor,
    ROUND(AVG(total_bayar), 0)   AS rata_rata_belanja_aov
FROM pesanan
WHERE status_pesanan = 'Selesai';

4. MIN & MAX: Transaksi Ekstrem & Rentang Waktu

Penjelasan Penggunaan MIN & MAX

Fungsi MIN() dan MAX() tidak hanya bekerja pada nilai angka/rupiah, tetapi juga sangat berguna pada tipe tanggal DATETIME. MIN(tanggal_pesanan) memberi tahu tanggal pesanan paling awal, sedangkan MAX(tanggal_pesanan) memberi tahu transaksi paling terbaru.

SQL Query
-- Transaksi terendah, tertinggi, dan rentang tanggal order
SELECT 
    MIN(total_bayar)     AS belanja_terendah,
    MAX(total_bayar)     AS belanja_tertinggi,
    MIN(tanggal_pesanan) AS order_pertama,
    MAX(tanggal_pesanan) AS order_terakhir
FROM pesanan
WHERE status_pesanan = 'Selesai';

5. GROUP BY: Segmentasi Berdasarkan Dimensi Bisnis

GROUP BY mengelompokkan data berdasarkan nilai kolom tertentu. Setiap kolom di klausa SELECT yang bukan fungsi agregasi wajib didaftarkan di GROUP BY.

Mengapa Harus Dikelompokkan (Grouped)?

Mengetahui total omzet Rp 500 Juta saja belum cukup untuk pengambilan keputusan. Dengan GROUP BY mp.nama_metode, Direktur Bisnis bisa melihat metode mana (misal: GoPay, BCA Virtual Account, QRIS) yang paling banyak digunakan oleh pengguna.

SQL Query
-- Performa omzet per Metode Pembayaran
SELECT 
    mp.nama_metode,
    mp.tipe,
    COUNT(p.pesanan_id) AS total_transaksi,
    SUM(p.total_bayar)  AS total_omzet_masuk
FROM pesanan p
JOIN metode_pembayaran mp ON p.metode_id = mp.metode_id
WHERE p.status_pesanan = 'Selesai'
GROUP BY mp.metode_id
ORDER BY total_omzet_masuk DESC;

6. HAVING vs WHERE

Aturan Emas: Kapan Menggunakan WHERE vs HAVING?
  • Gunakan WHERE untuk menyaring baris sebelum dihitung (contoh: WHERE status_pesanan = 'Selesai').
  • Gunakan HAVING untuk menyaring hasil kalkulasi kelompok setelah dihitung (contoh: HAVING COUNT(pesanan_id) > 15 atau HAVING SUM(total_bayar) > 10000000). WHERE tidak bisa menerima fungsi agregasi SUM/COUNT!
KlausaWaktu EksekusiObjek yang DifilterBisa Pakai Agregat?
WHERESebelum GroupingBaris individual data mentahTidak Bisa
HAVINGSetelah GroupingHasil kelompok agregat (SUM, COUNT)Bisa (Wajib)
SQL Query
-- Kota dengan kontribusi pesanan > 20 transaksi dan omzet > Rp 15.000.000
SELECT 
    ap.kota,
    COUNT(p.pesanan_id) AS jumlah_pesanan,
    SUM(p.total_bayar)  AS total_omzet_kota
FROM pesanan p
JOIN alamat_pelanggan ap ON p.alamat_kirim_id = ap.alamat_id
WHERE p.status_pesanan = 'Selesai'
GROUP BY ap.kota
HAVING jumlah_pesanan > 15
   AND total_omzet_kota > 10000000
ORDER BY total_omzet_kota DESC;
