Modul 04 — Tingkat Menengah

JOIN & Relasi Multi-Tabel E-Commerce

Database e-commerce yang baik dinormalisasi ke banyak tabel terpisah (produk, variasi, pesanan, kurir, pelanggan) untuk efisiensi penyimpanan. JOIN adalah jembatan untuk merekonstruksi kembali data tersebut menjadi satu laporan terpadu.

50 menit Menengah Database: E-Commerce Indonesia (20 Tabel) sql/04_join.sql

1. Konsep Normalisasi & Relasi Kunci (PK / FK)

Dalam database e-commerce, relasi dibentuk melalui Primary Key (PK) sebagai ID unik tabel asal dan Foreign Key (FK) sebagai kolom penunjuk di tabel tujuan. 

[kategori] (kategori_id PK)
    │
    └──< [subkategori] (subkategori_id PK, kategori_id FK)
            │
            └──< [produk] (produk_id PK, subkategori_id FK, merek_id FK, supplier_id FK)
                    │
                    └──< [variasi_produk] (variasi_id PK, produk_id FK)
                            │
                            └──< [rincian_pesanan] (rincian_id PK, variasi_id FK, pesanan_id FK)
                                    │
[pelanggan] ──< [pesanan] ──────────┘
                  │
                  ├──> [kurir_ekspedisi]
                  ├──> [metode_pembayaran]
                  └──> [voucher_promo]

2. INNER JOIN: Katalog Produk Lengkap

INNER JOIN hanya mengembalikan baris yang memiliki pasangan kecocokan di kedua tabel. Jika produk tidak memiliki merek, maka baris tersebut tidak akan muncul.

SQL Query
-- Menggabungkan Produk dengan Kategori, Subkategori, Merek, dan Supplier
SELECT 
    pr.produk_id,
    pr.nama_produk,
    m.nama_merek,
    k.nama_kategori,
    sk.nama_subkategori,
    s.nama_supplier,
    s.kota AS kota_supplier
FROM produk pr
INNER JOIN merek m        ON pr.merek_id = m.merek_id
INNER JOIN subkategori sk ON pr.subkategori_id = sk.subkategori_id
INNER JOIN kategori k    ON sk.kategori_id = k.kategori_id
INNER JOIN supplier s    ON pr.supplier_id = s.supplier_id
LIMIT 5;

3. LEFT JOIN & Analisis Churn (Anti-Join)

LEFT JOIN mempertahankan seluruh baris tabel kiri. Teknik ini sangat berguna untuk analisis retensi, misalnya: Mencari pelanggan yang telah mendaftar tetapi belum pernah melakukan pesanan (Inactive Users).

SQL Query
-- Anti-Join: Pelanggan yang belum pernah checkout
SELECT 
    pl.pelanggan_id,
    pl.nama_lengkap,
    pl.email,
    pl.tanggal_daftar
FROM pelanggan pl
LEFT JOIN pesanan p ON pl.pelanggan_id = p.pelanggan_id
WHERE p.pesanan_id IS NULL
LIMIT 5;

4. Rantai 6 Tabel: Rincian Lengkap Pembelian Pelanggan

SQL Query
-- Rekonstruksi transaksi belanja utuh lintas 6 tabel
SELECT 
    p.nomor_invoice,
    pl.nama_lengkap     AS nama_pembeli,
    pr.nama_produk,
    vp.warna,
    vp.ukuran,
    rp.jumlah           AS qty_beli,
    rp.harga_satuan,
    rp.subtotal,
    ke.nama_kurir       AS kurir_pengirim,
    mp.nama_metode      AS pembayaran
FROM pesanan p
JOIN pelanggan pl        ON p.pelanggan_id = pl.pelanggan_id
JOIN rincian_pesanan rp  ON p.pesanan_id = rp.pesanan_id
JOIN variasi_produk vp   ON rp.variasi_id = vp.variasi_id
JOIN produk pr           ON vp.produk_id = pr.produk_id
JOIN kurir_ekspedisi ke  ON p.kurir_id = ke.kurir_id
JOIN metode_pembayaran mp ON p.metode_id = mp.metode_id
LIMIT 5;

5. CROSS JOIN (Matrix Kombinasi)

SQL Query
-- Membuat matriks kombinasi seluruh Kategori dengan seluruh Gudang
SELECT 
    k.nama_kategori,
    g.nama_gudang,
    g.kota
FROM kategori k
CROSS JOIN gudang g
LIMIT 6;
