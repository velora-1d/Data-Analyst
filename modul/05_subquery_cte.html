Subquery & Common Table Expressions (CTE)

Saat analisis e-commerce membutuhkan pemfilteran dinamis terhadap rata-rata belanja global, atau pemrosesan logika bertahap seperti customer tiering dan profit margin, Subquery dan CTE adalah alat utama yang wajib dikuasai.

50 menit Mahir Unduh File SQL (05_subquery_cte.sql) Unduh ecommerce.db

1. Pengantar Subquery vs CTE

Subquery adalah query yang disematkan di dalam query lain (inner query). Kelemahannya adalah jika terlalu bersarang (nested), query menjadi sulit dibaca.

CTE (Common Table Expression) dengan klausa WITH ... AS memungkinkan kita mendefinisikan temporary result set bernama yang membuat kode mudah dibaca secara linier dari atas ke bawah seperti paragraf logika.

2. Scalar Subquery (Perbandingan Nilai Tunggal)

Scalar subquery menghasilkan tepat 1 baris dan 1 kolom. Sangat ideal untuk membandingkan nilai transaksi per pesanan terhadap rata-rata AOV keseluruhan toko.

Buat Apa Scalar Subquery Digunakan?

Saat Anda ingin menyaring transaksi yang nilainya di atas rata-rata toko, Anda tidak bisa mengetik angka rata-rata secara manual karena nilainya berubah terus setiap ada transaksi baru. Scalar subquery secara dinamis menghitung (SELECT AVG(total_bayar) FROM pesanan) lalu menggunakannya sebagai pembanding.

SQL Query
-- Transaksi yang nilainya melebihi rata-rata belanja (AOV) toko
SELECT 
    nomor_invoice,
    total_bayar,
    (SELECT ROUND(AVG(total_bayar), 0) FROM pesanan WHERE status_pesanan = 'Selesai') AS aov_global
FROM pesanan
WHERE status_pesanan = 'Selesai'
  AND total_bayar > (SELECT AVG(total_bayar) FROM pesanan WHERE status_pesanan = 'Selesai')
ORDER BY total_bayar DESC
LIMIT 5;

3. Multi-Row Subquery dengan Operator IN

Subquery yang menghasilkan daftar nilai ID dapat dipasangkan dengan operator IN.

Skenario Bisnis: Profiling Target Marketing

Tim Marketing ingin meluncurkan campaign promo aksesoris gadget khusus kepada pengguna yang pernah membeli produk 'Elektronik & Gadget'. Subquery bagian dalam mengumpulkan daftar pelanggan_id yang relevan, lalu query utama mengambil kontak pelanggan tersebut.

SQL Query
-- Mengambil daftar pelanggan yang pernah membeli produk kategori 'Elektronik & Gadget'
SELECT pelanggan_id, nama_lengkap, email, no_hp
FROM pelanggan
WHERE pelanggan_id IN (
    SELECT DISTINCT p.pelanggan_id
    FROM pesanan p
    JOIN rincian_pesanan rp  ON p.pesanan_id = rp.pesanan_id
    JOIN variasi_produk vp   ON rp.variasi_id = vp.variasi_id
    JOIN produk pr           ON vp.produk_id = pr.produk_id
    JOIN subkategori sk      ON pr.subkategori_id = sk.subkategori_id
    JOIN kategori k          ON sk.kategori_id = k.kategori_id
    WHERE k.nama_kategori = 'Elektronik & Gadget'
)
LIMIT 5;

4. Correlated Subquery

Correlated subquery bergantung pada nilai baris tabel luar (outer query) yang sedang diproses.

Cara Kerja Correlated Subquery

Tidak seperti subquery biasa yang dieksekusi sekali di awal, correlated subquery dieksekusi berulang kali untuk setiap baris tabel utama pelanggan pl. Syarat p.pelanggan_id = pl.pelanggan_id menyambungkan konteks baris luar ke dalam subquery.

SQL Query
-- Menghitung jumlah pesanan per pelanggan secara correlated
SELECT 
    pl.pelanggan_id,
    pl.nama_lengkap,
    (
        SELECT COUNT(*) 
        FROM pesanan p 
        WHERE p.pelanggan_id = pl.pelanggan_id 
          AND p.status_pesanan = 'Selesai'
    ) AS total_pesanan_selesai
FROM pelanggan pl
ORDER BY total_pesanan_selesai DESC
LIMIT 5;

5. Operator EXISTS & NOT EXISTS

Mengapa EXISTS Lebih Cepat daripada IN?

Operator EXISTS menggunakan mekanisme Short-Circuit Evaluation. Begitu engine menemukan setidaknya 1 baris transaksi yang cocok pada SELECT 1 FROM pesanan, pencarian langsung dihentikan tanpa perlu membaca seluruh sisa baris di tabel pesanan.

SQL Query
-- Menemukan voucher promo yang benar-benar pernah berhasil digunakan
SELECT vp.voucher_id, vp.kode_voucher, vp.nilai_diskon
FROM voucher_promo vp
WHERE EXISTS (
    SELECT 1 
    FROM pesanan p 
    WHERE p.voucher_id = vp.voucher_id 
      AND p.status_pesanan = 'Selesai'
);

6. Common Table Expression (WITH ... AS)

Buat Apa CTE (WITH ... AS) Diciptakan?

CTE membuat kode SQL yang sangat rumit menjadi modular dan mudah dibaca seperti fungsi pemrograman. Blok WITH CustomerSpending AS (...) membuat tabel sementara yang bersih, sehingga query utama di bawahnya tinggal mengambil hasilnya dengan klausa SELECT ... FROM CustomerSpending.

SQL Query
-- CTE: Analisis Segmentasi Spending Tier Pelanggan
WITH CustomerSpending AS (
    SELECT 
        pl.pelanggan_id,
        pl.nama_lengkap,
        COUNT(p.pesanan_id) AS total_orders,
        SUM(p.total_bayar)  AS total_spent
    FROM pelanggan pl
    LEFT JOIN pesanan p ON pl.pelanggan_id = p.pelanggan_id AND p.status_pesanan = 'Selesai'
    GROUP BY pl.pelanggan_id
)
SELECT 
    pelanggan_id,
    nama_lengkap,
    total_orders,
    COALESCE(total_spent, 0) AS total_belanja,
    CASE 
        WHEN total_spent >= 10000000 THEN 'VIP / Diamond'
        WHEN total_spent >= 3000000  THEN 'Gold Customer'
        WHEN total_spent > 0        THEN 'Regular Customer'
        ELSE 'Inactive / Lead'
    END AS kasta_pelanggan
FROM CustomerSpending
ORDER BY total_spent DESC
LIMIT 5;

7. Multi-Level CTE Pipeline

Beberapa CTE dapat dirangkai berurutan dipisahkan tanda koma untuk membentuk pipeline data analitik.

SQL Query
-- Pipeline Multi-CTE: Total Omzet Kategori -> Rata-rata Toko -> Status Performa
WITH CategorySales AS (
    SELECT 
        k.nama_kategori,
        SUM(rp.subtotal) AS total_omzet
    FROM rincian_pesanan rp
    JOIN variasi_produk vp ON rp.variasi_id = vp.variasi_id
    JOIN produk pr         ON vp.produk_id = pr.produk_id
    JOIN subkategori sk    ON pr.subkategori_id = sk.subkategori_id
    JOIN kategori k        ON sk.kategori_id = k.kategori_id
    GROUP BY k.kategori_id
),
GlobalBenchmark AS (
    SELECT AVG(total_omzet) AS rata_rata_omzet_kategori FROM CategorySales
)
SELECT 
    cs.nama_kategori,
    cs.total_omzet,
    ROUND(gb.rata_rata_omzet_kategori, 0) AS benchmark_toko,
    CASE 
        WHEN cs.total_omzet > gb.rata_rata_omzet_kategori THEN 'Di Atas Benchmark'
        ELSE 'Di Bawah Benchmark'
    END AS performa_kategori
FROM CategorySales cs
CROSS JOIN GlobalBenchmark gb
ORDER BY cs.total_omzet DESC;
