Tipe Data SQL di Industri E-Commerce

Sebelum menulis analisis data yang rumit, seorang praktisi data wajib memahami bagaimana database relasional menyimpan dan menginterpretasikan data. Kesalahan memahami tipe data dapat berakibat fatal pada perhitungan omzet finansial, pelacakan waktu pesanan, dan validitas laporan bisnis.

1. Pengantar Tipe Data String: VARCHAR vs CHAR vs TEXT

Di industri database profesional (PostgreSQL, MySQL, Oracle, SQL Server), tipe data teks dibagi secara spesifik sesuai efisiensi memori dan kebutuhan validasi panjang karakter:

Tipe Data SQL Sifat Penyimpanan Batas Panjang Kapan Digunakan di E-Commerce?
VARCHAR(n) Variable Character (panjang dinamis sesuai isi teks) Maksimal n karakter (misal VARCHAR(150)) Nama lengkap, email pembeli, judul produk, nomor resi kurir
CHAR(n) Fixed Character (panjang selalu tetap, diisi spasi jika kurang) Tepat n karakter (misal CHAR(5)) Kode Pos Indonesia (5 digit), Kode Negara ('ID'), Gender ('Pria')
TEXT Large Character Object (teks sangat panjang tanpa batas kaku) Bisa jutaan karakter (CLOB) Deskripsi spesifikasi produk, ulasan/review pelanggan, log error
INTEGER Bilangan bulat presisi (tanpa koma) -9 Triliun s/d +9 Triliun (8-byte) Mata uang Rupiah (IDR bulat), jumlah stok barang, quantity belanja
REAL / DECIMAL Bilangan desimal / floating point Pecahan presisi tinggi Rating bintang (4.8), bobot dalam kg (1.25 kg), persentase margin laba
DATETIME Waktu transaksi standar ISO-8601 Format: YYYY-MM-DD HH:MM:SS Waktu pesanan dibuat, tanggal bayar, riwayat update status kurir

2. Bagaimana SQLite Memperlakukan VARCHAR dan CHAR?

Jika Anda membuat tabel dengan nama_lengkap VARCHAR(150) atau kode_pos CHAR(5) di SQLite, SQLite menerimanya secara 100% valid.

Namun, di bawah kap mesinnya, SQLite menerapkan aturan yang disebut Type Affinity:

Prinsip Type Affinity SQLite:

Semua tipe data yang mengandung kata CHAR, VARCHAR, TEXT, atau CLOB secara otomatis dimasukkan ke dalam kelas penyimpanan TEXT Affinity. Hal ini membuat SQLite sangat fleksibel dan ringan, namun tetap kompatibel dengan DDL database enterprise lainnya.

4. Relasi Antar Tabel: Primary Key (PK), Foreign Key (FK) & Diagram ERD

Dalam database relasional bisnis e-commerce (20 Tabel), data tidak disimpan dalam 1 lembar spreadsheet raksasa, melainkan dipecah ke dalam tabel-tabel terpisah untuk menghindari duplikasi (normalisasi). Kunci hubungan antar tabel ditentukan oleh Primary Key (PK) dan Foreign Key (FK).

Istilah Relasi Definisi Teknis Contoh pada Database E-Commerce Ini
Primary Key (PK) Kolom unik penanda utama tiap baris data. Tidak boleh bernilai NULL dan tidak boleh ada duplikat. pelanggan_id pada tabel pelanggan, pesanan_id pada tabel pesanan.
Foreign Key (FK) Kolom pada suatu tabel yang merujuk/menunjuk ke PRIMARY KEY di tabel lain untuk menghubungkan transaksi. pesanan.pelanggan_id (FK) yang merujuk ke pelanggan.pelanggan_id (PK).
Kardinalitas (1:N) Hubungan One-to-Many: Satu baris induk di tabel PK dapat terhubung ke banyak baris anak di tabel FK. 1 pelanggan dapat memiliki N pesanan. 1 pesanan dapat memiliki N rincian_pesanan (item barang).

5. Tipe TEXT & Manipulasi Karakter

Tipe TEXT menyimpan data alfabet, simbol, dan alfanumerik. Manipulasi teks sangat krusial untuk data cleaning, seperti menstandarkan huruf besar/kecil, menggabungkan alamat, atau menyamarkan nomor HP pribadi (data privacy).

SQL Query 
-- Eksplorasi fungsi string pada data pelanggan
SELECT 
    pelanggan_id,
    nama_lengkap,
    UPPER(nama_lengkap)                  AS nama_uppercase,
    LOWER(email)                         AS email_clean,
    LENGTH(nama_lengkap)                 AS panjang_karakter,
    SUBSTR(no_hp, 1, 4) || '-xxxx-xxxx' AS no_hp_masking,
    typeof(nama_lengkap)                 AS tipe_data
FROM pelanggan
LIMIT 5;

Simbol || adalah operator penggabung (string concatenation) standar SQL.
Penjelasan Detail Fungsi Manipulasi Teks (String):
  • UPPER(nama_lengkap) — Mengubah semua huruf menjadi kapital. Digunakan untuk menstandarkan teks agar pencarian nama bersifat case-insensitive.
  • LOWER(email) — Mengubah alamat email menjadi huruf kecil. Sangat penting pada tahap Data Cleaning agar data email konsisten.
  • LENGTH(nama_lengkap) — Menghitung jumlah karakter dalam string. Berguna untuk validasi input (misal memeriksa panjang NIK, nomor telepon, atau nama minimum).
  • SUBSTR(no_hp, 1, 4) || '-xxxx-xxxx' — Data Masking (Privasi Data / PII): Mengambil 4 digit awal prefix operator HP dengan SUBSTR() lalu menggabungkannya (||) dengan pola rahasia demi mematuhi regulasi Undang-Undang Perlindungan Data Pribadi (UU PDP).
  • typeof(nama_lengkap) — Memeriksa tipe data riil dari isi kolom secara dinamis di SQLite untuk memastikan tipe data tersimpan sebagai text.

6. Tipe INTEGER & Operasi Finansial Rupiah

Dalam sistem transaksi di Indonesia, mata uang Rupiah biasanya disimpan sebagai INTEGER bulat tanpa pecahan sen. Hal ini menghindari bug floating-point rounding yang sering terjadi pada tipe float.

SQL Query 
-- Perhitungan laba kotor per SKU variasi produk
SELECT 
    variasi_id,
    sku,
    warna,
    ukuran,
    harga_modal,
    harga_jual,
    harga_jual - harga_modal  AS laba_kotor_rp,
    typeof(harga_jual)          AS tipe_harga
FROM variasi_produk
LIMIT 5;

Peringatan Pembagian Integer di SQL

Di SQLite, jika Anda membagi dua angka integer misalnya 100 / 3, hasilnya adalah bilangan bulat 33 (dibulatkan ke bawah), bukan 33.33. Anda harus mengonversinya ke REAL terlebih dahulu jika membutuhkan desimal.

7. Tipe REAL & Fungsi Pembulatan ROUND()

Tipe REAL digunakan untuk nilai metrik yang memiliki desimal seperti rating ulasan pelanggan (contoh: 4.8 bintang), rasio diskon persentase, atau berat barang dalam kilogram.

SQL Query 
-- Menghitung berat paket dalam kilogram (kg) dan rating desimal
SELECT 
    nomor_invoice,
    total_berat_gram,
    CAST(total_berat_gram AS REAL) / 1000.0 AS berat_kg,
    ROUND(CAST(total_berat_gram AS REAL) / 1000.0, 1) AS berat_kg_bulat
FROM pesanan
LIMIT 5;

8. Tipe DATETIME (Analisis Waktu Transaksi)

Di SQLite, tanggal dan waktu disimpan dalam format teks standar ISO-8601 yaitu YYYY-MM-DD HH:MM:SS. Kita menggunakan fungsi STRFTIME() dan DATE() untuk membedah pola waktu belanja pelanggan.

SQL Query 
-- Ekstraksi komponen waktu transaksi untuk analisis tren
SELECT 
    nomor_invoice,
    tanggal_pesanan,
    DATE(tanggal_pesanan)                    AS tanggal_saja,
    STRFTIME('%Y', tanggal_pesanan)         AS tahun_order,
    STRFTIME('%m', tanggal_pesanan)         AS bulan_order,
    STRFTIME('%Y-%m', tanggal_pesanan)      AS periode_bulanan,
    STRFTIME('%H', tanggal_pesanan)         AS jam_checkout
FROM pesanan
LIMIT 5;

9. Tipe Nilai NULL (Missing Data & Unknown State)

Di dalam database relasional, NULL bukanlah sebuah nilai biasa. NULL adalah Storage Class khusus di SQLite yang menandakan bahwa suatu data tidak ada, belum diketahui, atau tidak berlaku (missing value / absence of data).

Kesalahan Fatal Pemula: NULL Bukan Nol (0) dan Bukan Teks Kosong ('')

Banyak analis data pemula menyamakan NULL dengan angka 0 atau string kosong ''. Padahal secara logika dan penyimpanan, ketiganya memiliki status yang sangat berbeda di database.

NilaiArti di Bisnis E-CommerceTipe / Storage ClassContoh di Tabel
NULL Data tidak ada / belum diisi / tidak memakai fasilitas NULL Pesanan tidak memakai kupon promo (voucher_id IS NULL)
0 Ada nilainya dan bernilai nol rupiah / nol unit INTEGER Promo bebas ongkos kirim (ongkir = 0)
'' (Empty String) Teks ada namun tanpa karakter sama sekali (panjang 0) TEXT Kolom catatan pesanan dikosongkan pembeli
'NULL' Teks biasa dengan 4 huruf N-U-L-L (seringkali bug aplikasi backend!) TEXT Salah input teks nama pelanggan yang bertuliskan "NULL"

Logika Tiga Nilai (Three-Valued Logic / 3VL)

Di SQL standar, evaluasi perbandingan tidak hanya menghasilkan TRUE atau FALSE, tetapi bisa menghasilkan UNKNOWN jika melibatkan nilai NULL.

Mengapa WHERE voucher_id = NULL Selalu Gagal?

Ekspresi NULL = NULL tidak bernilai TRUE, melainkan UNKNOWN. Database menganggap "sesuatu yang tidak kita ketahui tidak bisa dipastikan sama dengan sesuatu yang lain yang juga tidak kita ketahui". Karena itu, Anda wajib menggunakan operator khusus IS NULL dan IS NOT NULL.

4 Fungsi Esensial Penanganan Nilai NULL di SQL

Fungsi / OperatorCara KerjaContoh Query
IS NULL / IS NOT NULL Memfilter baris data yang kosong atau yang terisi WHERE voucher_id IS NULL
COALESCE(val1, val2, ...) Mengembalikan nilai non-NULL pertama dari daftar argumen COALESCE(voucher_id, 0)
IFNULL(val, default) Shorthand khas SQLite/MySQL untuk mengganti NULL dengan nilai default IFNULL(potongan_diskon, 0)
NULLIF(a, b) Mengembalikan NULL jika nilai a = b (mencegah error pembagian dengan nol) total / NULLIF(jumlah_barang, 0)
SQL Query 
-- Praktik Penanganan Nilai NULL pada Transaksi E-Commerce
SELECT 
    nomor_invoice,
    total_bayar,
    voucher_id,
    -- 1. Mengelompokkan jenis transaksi dengan IS NULL
    CASE 
        WHEN voucher_id IS NULL THEN 'Tanpa Diskon'
        ELSE 'Klaim Voucher'
    END AS status_voucher,
    -- 2. Imputasi nilai NULL menjadi angka 0 dengan COALESCE
    COALESCE(voucher_id, 0) AS voucher_id_bersih,
    -- 3. Mencegah error pembagian dengan nol menggunakan NULLIF
    ROUND(total_bayar / NULLIF(total_berat_gram, 0), 2) AS rupiah_per_gram
FROM pesanan
LIMIT 5;
Pengaruh NULL pada Fungsi Agregasi COUNT:

- COUNT(*) menghitung seluruh baris transaksi (termasuk yang bernilai NULL).
- COUNT(voucher_id) hanya menghitung baris yang NON-NULL (pesanan yang memakai voucher). Baris NULL diabaikan otomatis!

10. Kolom UNIQUE & Tipe Identifier Unik (UUID)

Banyak pemula menyebut "tipe data unique". Secara kaidah teknis database SQL, UNIQUE bukanlah sebuah tipe data fisik, melainkan sebuah Constraint (Batasan Integritas Kolom). Tipe data fisiknya tetap berupa TEXT, VARCHAR, atau INTEGER, namun mesin database diberikan aturan ketat: "Tidak boleh ada 2 baris data yang memiliki nilai kembar pada kolom ini!".

Mengapa Kolom UNIQUE Sangat Kritis di E-Commerce?

Tanpa aturan UNIQUE, integritas database e-commerce akan rusak:

  • Tabel Pelanggan (email & no_hp): Mencegah satu orang mendaftar berkali-kali untuk menyalahgunakan bonus pendaftaran (*voucher abuse*).
  • Tabel Pesanan (nomor_invoice): Mencegah tagihan ganda atau pesanan duplikat dengan nomor yang sama.
  • Tabel Produk (sku): Kode Stock Keeping Unit wajib unik agar sistem pergudangan tidak salah mengirim variasi barang.
  • Tabel Kupon (kode_voucher): Kode kupon (misal: PAYDAY99) tidak boleh ganda dengan persentase diskon yang bertabrakan.

Perbedaan PRIMARY KEY vs UNIQUE Constraint

KarakteristikPRIMARY KEYUNIQUE Constraint
Batas Jumlah per Tabel Hanya 1 kolom (atau 1 kombinasi composite key) Bisa banyak kolom dalam satu tabel (misal email UNIQUE, no_hp UNIQUE, nomor_ktp UNIQUE)
Bolehkah Bernilai NULL? MUTLAK TIDAK BOLEH (wajib NOT NULL) BOLEH bernilai NULL (kecuali ditambahkan aturan NOT NULL). Di SQL standar, dua baris bernilai NULL tidak dianggap duplikat karena NULL tidak sama dengan NULL.
Peran Utama Identitas permanen baris untuk referensi Foreign Key Mencegah duplikasi data bisnis (Integritas Data)
Indeks Otomatis Otomatis dibuatkan Clustered / Unique Index Otomatis dibuatkan Unique Index untuk pencarian kilat

Tipe Identifier Unik: Auto-Increment Integer vs UUID

Saat membuat kolom ID unik untuk sistem modern, ada 2 pendekatan utama di industri teknologi:

Jenis IDFormat & Tipe DataKelebihanKekurangan di E-Commerce
Auto-Increment INTEGER (1, 2, 3, 4, ...) Sangat hemat memori storage, pengurutan waktu otomatis sesuai nomor urut Rentan Business Intelligence Leak: Kompetitor bisa menebak volume order harian Anda (misal belanja pagi invoice #100, belanja sore invoice #500 = ada 400 order/hari!).
UUID / GUID (v4) TEXT / VARCHAR(36)
Contoh: c3a8b2d1-4e7f-4a3b-9c12-8d9e0f1a2b3c		 Aman secara bisnis (tidak bisa ditebak), sangat ideal untuk arsitektur microservices terdistribusi tanpa risiko bentrok ID saat merger data. Ukuran index lebih besar (36 bytes vs 4-8 bytes pada integer).
SQL Query 
-- 1. Penerapan Constraint UNIQUE pada DDL Pembuatan Tabel Baru
CREATE TABLE IF NOT EXISTS akun_reseller (
    reseller_id   INTEGER PRIMARY KEY AUTOINCREMENT,
    kode_reseller VARCHAR(20) NOT NULL UNIQUE,       -- Wajib Unik (Tidak boleh kembar)
    email         VARCHAR(100) NOT NULL UNIQUE,      -- Wajib Unik
    nomor_rekeningVARCHAR(30) UNIQUE,                -- Boleh NULL jika belum diisi, tapi jika ada tidak boleh kembar
    nama_toko     TEXT NOT NULL
);

-- 2. Contoh Query Data Analyst: Audit & Deteksi Data Duplikat di Sistem
SELECT 
    email,
    COUNT(*) AS total_kemunculan
FROM pelanggan
GROUP BY email
HAVING COUNT(*) > 1;
Apa yang Terjadi Jika Memasukkan Data Kembar pada Kolom UNIQUE?

Database engine akan langsung menolak transaksi dan melempar error: Runtime error: UNIQUE constraint failed: pelanggan.email. Data yang korup tidak akan pernah berhasil masuk ke dalam database!

11. Type Casting dengan CAST()

Fungsi CAST(ekspresi AS tipe_tujuan) digunakan untuk mengonversi tipe data secara eksplisit pada saat query berjalan. Sangat dibutuhkan saat menghitung margin laba persentase.

SQL Query 
-- Menghitung persentase profit margin per variasi produk
SELECT 
    sku,
    harga_modal,
    harga_jual,
    harga_jual - harga_modal AS profit_rp,
    ROUND(
        (CAST(harga_jual - harga_modal AS REAL) / harga_jual) * 100, 
        2
    ) AS profit_margin_percent
FROM variasi_produk
LIMIT 5;

12. DDL & DML: Desain Tabel & Manipulasi Data

Selain membaca data (query SELECT), pengolahan data SQL melibatkan 2 kelompok perintah utama: DDL (Data Definition Language) untuk mendefinisikan struktur skema tabel, dan DML (Data Manipulation Language) untuk memanipulasi isi baris data.

A. Data Definition Language (DDL)

Digunakan untuk membuat (CREATE TABLE), mengubah struktur (ALTER TABLE), dan menghapus struktur tabel (DROP TABLE).

DDL: Membuat & Mengubah Tabel 
-- 1. CREATE TABLE: Membuat tabel kategori promo baru dengan Constraints
CREATE TABLE IF NOT EXISTS kategori_promo (
    kategori_id   INTEGER PRIMARY KEY AUTOINCREMENT,
    nama_kategori VARCHAR(50) NOT NULL UNIQUE,
    diskon_pct    REAL DEFAULT 0.0,
    status_aktif  INTEGER CHECK (status_aktif IN (0, 1)) DEFAULT 1
);

-- 2. ALTER TABLE: Menambah kolom baru catatan pada tabel

B. Data Manipulation Language (DML)

Digunakan untuk menambah (INSERT), memperbarui (UPDATE), dan menghapus isi baris data (DELETE).

DML: Manipulasi Baris Data 
-- 1. INSERT: Menambah data promo baru
INSERT INTO kategori_promo (nama_kategori, diskon_pct, status_aktif)
VALUES 
    ('Flash Sale Payday', 25.5, 1),
    ('Diskon Ongkir Super', 10.0, 1);

-- 2. UPDATE: Memperbarui nilai diskon promo khusus
UPDATE kategori_promo
SET diskon_pct = 30.0, catatan = 'Promo Khusus Tanggal Kembar'
WHERE nama_kategori = 'Flash Sale Payday';

-- 3. DELETE: Menghapus baris promo yang sudah dinonaktifkan
DELETE FROM kategori_promo
WHERE status_aktif = 0;
Penting: DELETE vs TRUNCATE TABLE

Perintah DELETE FROM tabel WHERE ... menghapus baris data spesifik berdasarkan kondisi. Jika klausa WHERE dihilangkan, seluruh baris data akan terhapus. Di database enterprise (MySQL/PostgreSQL/Oracle), perintah TRUNCATE TABLE digunakan untuk mengosongkan isi tabel secara instan dan mereset nomor urut auto-increment.
