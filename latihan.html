Pemilihan Kolom Tertentu & Pembatasan Baris
Klausa: SELECT • FROM • LIMIT
SELECT & LIMIT
Kasus Bisnis: Tim operasional logistik ingin melihat katalog produk beserta bobot barang dalam gram untuk memperkirakan kebutuhan kapasitas kardus packing pengiriman.
Tabel Target
produk
Kolom Diminta
nama_produk, berat_gram
Batasan Baris
5 baris pertama
Petunjuk: Gunakan klausa LIMIT 5 di akhir query untuk membatasi jumlah data yang ditarik.
Kotak Uji Query Anda:
Kunci Jawaban Soal 1 Status: Terverifikasi di ecommerce.db 
SELECT 
    nama_produk, 
    berat_gram
FROM produk
LIMIT 5;
Pembahasan Logika:
  • SELECT nama_produk, berat_gram: Hanya mengambil 2 kolom yang relevan sehingga hemat memori.
  • FROM produk: Menentukan tabel sumber data.
  • LIMIT 5: Menghentikan scan mesin SQLite setelah menemukan 5 record pertama.

Alias Kolom & Kalkulasi Margin Keuntungan
Klausa: AS • Operator Matematika (-)
AS & Kalkulasi
Kasus Bisnis: Manajer keuangan ingin menghitung estimasi keuntungan kotor nominal (margin rupiah) per unit untuk setiap variasi barang yang dijual.
Tabel Target
variasi_produk
Kolom Diminta
sku, harga_modal, harga_jual
Kolom Kalkulasi
harga_jual - harga_modal AS keuntungan_nominal
Batasan Baris
5 baris pertama
Petunjuk: Kurangi harga_jual dengan harga_modal di klausa SELECT dan namai dengan kata kunci AS keuntungan_nominal.
Kotak Uji Query Anda:
Kunci Jawaban Soal 2 Status: Terverifikasi di ecommerce.db 
SELECT 
    sku,
    harga_modal,
    harga_jual,
    (harga_jual - harga_modal) AS keuntungan_nominal
FROM variasi_produk
LIMIT 5;
Pembahasan Logika:
  • SQL mendukung operator matematika standar seperti +, -, *, / langsung di klausa SELECT.
  • Tanda kurung (harga_jual - harga_modal) membantu memperjelas prioritas kalkulasi aritmatika.
  • AS keuntungan_nominal memberi nama kolom yang jelas bagi tim frontend/laporan tanpa mengubah struktur tabel fisik.

Filter Transaksi Selesai Bernilai Tinggi (WHERE >=)
Klausa: WHERE • AND • ORDER BY ASC
WHERE & Operator >=
Kasus Bisnis: Divisi audit keuangan ingin meninjau pesanan yang telah sukses dikirim (status 'Selesai') dan bernilai pembayaran Rp 1.000.000 ke atas.
Tabel Target
pesanan
Kondisi Filter
status_pesanan = 'Selesai' AND total_bayar >= 1000000
Pengurutan
ORDER BY total_bayar ASC (Termurah dulu)
Batasan Baris
5 baris pertama
Petunjuk: Gunakan operator perbandingan >= 1000000 dan rangkai dengan AND.
Kotak Uji Query Anda:
Kunci Jawaban Soal 3 Status: Terverifikasi di ecommerce.db 
SELECT 
    nomor_invoice, 
    tanggal_pesanan, 
    total_bayar, 
    status_pesanan
FROM pesanan
WHERE status_pesanan = 'Selesai'
  AND total_bayar >= 1000000
ORDER BY total_bayar ASC
LIMIT 5;
Pembahasan Logika:
  • Klausa WHERE memfilter baris sebelum dikelompokkan atau diurutkan.
  • Kombinasi AND mewajibkan kedua kondisi bernilai benar (TRUE).
  • ORDER BY total_bayar ASC mengurutkan dari nominal terendah yang memenuhi syarat batas 1 juta.

Kombinasi String & Tanggal Pendaftaran
Klausa: WHERE • Format ISO 'YYYY-MM-DD'
Filter Tanggal & String
Kasus Bisnis: Tim CRM ingin membagikan voucher promo khusus bagi anggota pelanggan wanita yang mendaftar pada atau setelah 1 Januari 2023.
Tabel Target
pelanggan
Kondisi Filter
gender = 'Wanita' AND tanggal_daftar >= '2023-01-01'
Kolom Diminta
pelanggan_id, nama_lengkap, gender, tanggal_daftar, email
Batasan Baris
5 baris pertama
Petunjuk: Nilai tanggal diapit tanda kutip satu dengan format baku ISO 'YYYY-MM-DD'.
Kotak Uji Query Anda:
Kunci Jawaban Soal 4 Status: Terverifikasi di ecommerce.db 
SELECT 
    pelanggan_id, 
    nama_lengkap, 
    gender, 
    tanggal_daftar, 
    email
FROM pelanggan
WHERE gender = 'Wanita'
  AND tanggal_daftar >= '2023-01-01'
LIMIT 5;
Pembahasan Logika:
  • Format string teks dan tanggal di SQL wajib diapit tanda petik tunggal ('Wanita').
  • Tipe data tanggal ISO-8601 memungkinkan perbandingan leksikografis langsung dengan operator >=.

Eliminasi Duplikasi & Pengurutan Bertingkat
Klausa: DISTINCT • ORDER BY Kolom 1, Kolom 2
DISTINCT & ORDER BY
Kasus Bisnis: Tim ekspedisi kurir membutuhkan rekapitulasi daftar wilayah tujuan pengiriman tanpa duplikasi nama kota dan provinsi.
Tabel Target
alamat_pelanggan
Kolom Diminta
kota, provinsi (tanpa duplikat)
Pengurutan
provinsi ASC, lalu kota ASC
Batasan Baris
10 baris pertama
Petunjuk: Gunakan kata kunci SELECT DISTINCT untuk menghapus baris duplikat.
Kotak Uji Query Anda:
Kunci Jawaban Soal 5 Status: Terverifikasi di ecommerce.db 
SELECT DISTINCT 
    kota, 
    provinsi
FROM alamat_pelanggan
ORDER BY provinsi ASC, kota ASC
LIMIT 10;
Pembahasan Logika:
  • DISTINCT menghapus seluruh baris yang memiliki pasangan nilai (kota, provinsi) yang persis sama.
  • ORDER BY provinsi ASC, kota ASC menerapkan pengurutan dua tingkat: mengurutkan provinsi secara alfabetis terlebih dahulu, kemudian kota di dalam provinsi tersebut.

Filter Himpunan Nilai Tertentu (Operator IN)
Klausa: WHERE ... IN ('Diproses', 'Dikirim')
Operator IN
Kasus Bisnis: Petugas fulfillment gudang ingin memantau antrean pesanan aktif yang statusnya sedang 'Diproses' atau sedang 'Dikirim'.
Tabel Target
pesanan
Kondisi Filter
status_pesanan IN ('Diproses', 'Dikirim')
Pengurutan
tanggal_pesanan DESC (Terbaru)
Batasan Baris
5 baris pertama
Petunjuk: Operator IN (...) jauh lebih efisien daripada menulis banyak kondisi OR.
Kotak Uji Query Anda:
Kunci Jawaban Soal 6 Status: Terverifikasi di ecommerce.db 
SELECT 
    nomor_invoice, 
    tanggal_pesanan, 
    status_pesanan, 
    total_bayar
FROM pesanan
WHERE status_pesanan IN ('Diproses', 'Dikirim')
ORDER BY tanggal_pesanan DESC
LIMIT 5;
Pembahasan Logika:
  • status_pesanan IN ('Diproses', 'Dikirim') mencocokkan baris mana pun yang nilainya ada dalam daftar himpunan.
  • ORDER BY tanggal_pesanan DESC memprioritaskan pesanan terbaru di paling atas agar segera ditindaklanjuti.

Filter Rentang Nilai Inklusif (Operator BETWEEN)
Klausa: WHERE ... BETWEEN 250000 AND 500000
Operator BETWEEN
Kasus Bisnis: Tim produk ingin mengamati transaksi bernilai belanja keranjang menengah, yaitu dengan total pembayaran antara Rp 250.000 hingga Rp 500.000.
Tabel Target
pesanan
Kondisi Filter
total_bayar BETWEEN 250000 AND 500000
Pengurutan
total_bayar DESC (Terbesar ke terkecil)
Batasan Baris
5 baris pertama
Petunjuk: BETWEEN nilai_awal AND nilai_akhir bersifat inklusif (kedua nilai batas ikut masuk).
Kotak Uji Query Anda:
Kunci Jawaban Soal 7 Status: Terverifikasi di ecommerce.db 
SELECT 
    nomor_invoice, 
    total_bayar, 
    status_pesanan
FROM pesanan
WHERE total_bayar BETWEEN 250000 AND 500000
ORDER BY total_bayar DESC
LIMIT 5;
Pembahasan Logika:
  • BETWEEN 250000 AND 500000 menghasilkan kode yang bersih dibandingkan menulis total_bayar >= 250000 AND total_bayar <= 500000.
  • ORDER BY total_bayar DESC menaruh nilai yang mendekati batas atas 500 ribu di urutan pertama.

Pencarian Pola Teks Wildcard (LIKE & OR)
Klausa: WHERE ... LIKE '%Wireless%' OR LIKE '%Gaming%'
LIKE & Wildcard
Kasus Bisnis: Pelanggan mencari aksesoris atau gadget bertema nirkabel atau gaming di katalog toko online.
Tabel Target
produk
Kondisi Filter
nama_produk mengandung 'Wireless' ATAU 'Gaming'
Kolom Diminta
produk_id, nama_produk, deskripsi
Petunjuk: Karakter persen % adalah wildcard pencocokan substring di posisi mana pun.
Kotak Uji Query Anda:
Kunci Jawaban Soal 8 Status: Terverifikasi di ecommerce.db 
SELECT 
    produk_id, 
    nama_produk, 
    deskripsi
FROM produk
WHERE nama_produk LIKE '%Wireless%'
   OR nama_produk LIKE '%Gaming%';
Pembahasan Logika:
  • LIKE '%Wireless%' mencocokkan kata "Wireless" baik di awal, tengah, maupun akhir nama produk.
  • Operator OR memastikan produk yang memuat salah satu kata kunci tersebut tetap lolos seleksi.

Paginasi Halaman Data (LIMIT & OFFSET)
Klausa: ORDER BY DESC • LIMIT 10 OFFSET 10
LIMIT & OFFSET
Kasus Bisnis: Pada dashboard sistem manajemen pesanan (OMS), daftar transaksi bernilai terbesar dimuat 10 transaksi per halaman. Pengguna sedang membuka Halaman ke-2.
Tabel Target
pesanan
Pengurutan
total_bayar DESC (Termahal dulu)
Halaman Target
Halaman 2 (Lewati 10 data pertama, ambil 10 berikutnya)
Petunjuk: Gunakan LIMIT 10 OFFSET 10 untuk melompati baris 1-10 dan mengambil baris 11-20.
Kotak Uji Query Anda:
Kunci Jawaban Soal 9 Status: Terverifikasi di ecommerce.db 
SELECT 
    nomor_invoice,

Pembahasan Logika:
  • LIMIT 10 menentukan ukuran per halaman (page size).
  • OFFSET 10 melompati 10 record peringkat 1 s/d 10 (Halaman 1) sehingga yang tampil murni record peringkat 11 s/d 20 (Halaman 2).

Pengecekan Nilai Kosong (IS NULL)
Klausa: WHERE voucher_id IS NULL
IS NULL
Kasus Bisnis: Analis e-commerce ingin mengevaluasi perilaku transaksi organik: pesanan mana saja yang dibuat tanpa menggunakan kode voucher diskon sama sekali.
Tabel Target
pesanan
Kondisi Filter
voucher_id IS NULL
Pengurutan
tanggal_pesanan DESC (Terbaru)
Batasan Baris
5 baris pertama
Petunjuk: Jangan gunakan = NULL. Standar SQL wajib menggunakan operator khusus IS NULL.
Kotak Uji Query Anda:
Kunci Jawaban Soal 10 Status: Terverifikasi di ecommerce.db 
SELECT 
    nomor_invoice, 
    potongan_diskon, 
    voucher_id, 
    total_bayar, 
    tanggal_pesanan
FROM pesanan
WHERE voucher_id IS NULL
ORDER BY tanggal_pesanan DESC
LIMIT 5;
Pembahasan Logika:
  • Nilai NULL menandakan ketiadaan nilai (pelanggan check-out tanpa voucher promo).
  • Perbandingan = NULL selalu bernilai UNKNOWN / FALSE dalam logika tiga nilai SQL, sehingga hanya operator IS NULL yang sah.
