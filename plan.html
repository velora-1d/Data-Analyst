Master Implementation Plan (10 Macro-Phases)

Struktur roadmap yang dikonsolidasi menjadi 10 Fase Terfokus. Setiap fase membawa target keluaran konkret yang membedah sistem dari prinsip pertama (*first principles*) hingga implementasi industri nyata tanpa beban abstraksi framework yang rumit.

Progres Penyelesaian 10 Macro-Phases 0% (0/10 Fase Selesai)
FASE 01 Fondasi Platform Foundation, Dynamic Navigation & Instant Search
Sedang Berjalan
Sasaran & First Principles
Mengintegrasikan portal kurikulum terpadu index.html dengan sistem Single Source of Truth (SSOT) via nav-data.json. Render accordion sidebar dinamis berbasis DocumentFragment untuk efisiensi DOM (1 kali reflow) dan pencarian lokal in-memory fuzzy search.
Deliverable & Lab Praktik
Portal beranda multi-track interaktif, sidebar modular yang membaca struktur materi secara otomatis, dan standarisasi visual callout (kegagalan produksi, trade-off, dan anti-pattern).
⚠️ Common Pitfall: Melakukan manipulasi DOM satu per satu di dalam perulangan yang memicu reflow thrashing.
✅ Definition of Done: Siswa dapat menavigasi kurikulum dari beranda dan menu sidebar aktif menyala otomatis dengan waktu muat 0ms.
FASE 02 Database Database Storage Engine, B+Tree & Indexing Optimization
Berikutnya
First Principles (Riset: Alex Petrov)
  • Slotted Page Layout (4KB): Header 100-byte, cell pointer array, free space gap, dan row payload.
  • B+Tree vs LSM-Tree: Leaf nodes B+Tree tersambung doubly linked list untuk range scan kilat; LSM-Tree (MemTable, WAL append, SSTables, Bloom Filter) untuk write-heavy.
  • Composite Indexing: Aturan emas Leftmost Prefix Rule dan Covering Index (Index Only Scan).
Deliverable & Lab Praktik
Inspeksi biner file ecommerce.db dan optimalisasi query lambat pada 5.600+ baris data transaksi dari SCAN TABLE menjadi SEARCH TABLE USING COVERING INDEX via EXPLAIN QUERY PLAN.
⚠️ Common Pitfall: Menggunakan fungsi pembungkus (WHERE YEAR(tgl) = 2024) yang menonaktifkan B-Tree index.
✅ Definition of Done: Siswa mampu mengeliminasi Full Table Scan dan mendokumentasikan penurunan latensi query secara empiris.
FASE 03 Database Transaksi Database, Konkurensi & Transaksi Terdistribusi
Terencana
Konkurensi ACID & Saga
4 Anomali ANSI SQL (Dirty, Non-Repeatable, Phantom, Serialization). 4 Level Isolasi. Two-Phase Locking (2PL), MVCC (Multi-Version Concurrency Control), dan Optimistic Concurrency Control (OCC). Transaksi Terdistribusi: Keterbatasan 2PC vs solusi modern Saga Pattern (Choreography vs Orchestration) dengan compensating transactions.
✅ Definition of Done: Simulasi penanganan race condition Flash Sale Checkout (stok = 1) dengan lock pesimistik yang bebas dari deadlock.
FASE 04 Frontend Browser Rendering Pipeline, Event Loop & Web Performance (60 FPS)
Terencana
Critical Rendering Path (CRP) & Event Loop
DOM -> CSSOM -> Render Tree -> Layout (Reflow) -> Paint -> Composite. Budget frame 16.6ms (60 FPS). Perbedaan properti pemicu Reflow (mahal) vs Paint vs GPU Composite (mulus: transform, opacity). Event Loop: Call Stack, Macrotasks, Microtasks (Promises), dan requestAnimationFrame.
⚠️ Common Pitfall: Forced Synchronous Layout / Layout Thrashing karena baca-tulis style DOM berulang di dalam perulangan.
✅ Definition of Done: Profiling menggunakan Chrome DevTools, menghilangkan jank, dan menghasilkan animasi interaktif 60 FPS zero-reflow.
FASE 05 Frontend Modern CSS Architecture, Responsive Grid & Design Tokens
Terencana
Layout Algorithms & Tokens
Algoritma 1D Flexbox vs 2D CSS Grid. CSS Custom Properties untuk sistem token warna cascading. Implementasi Dark Mode instan tanpa flicker via atribut data-theme. Komparasi arsitektur industri: BEM vs Utility-first (Tailwind) vs CSS-in-JS.
✅ Definition of Done: Responsive grid auto-fit minmax tanpa media query, zero CLS (Cumulative Layout Shift = 0), dan palet warna biru modern.
FASE 06 Frontend Paradigma Framework Frontend & Arsitektur State Management
Terencana
Reaktivitas & Rendering
Virtual DOM Diffing (React) vs Compile-Time Reactivity (Svelte) vs Fine-Grained Signals (Solid/Vue). Model rendering CSR, SSR, SSG, ISR, dan Islands Architecture. Arsitektur pemisahan UI State lokal vs Server Cache State (TanStack Query stale-while-revalidate pattern).
✅ Definition of Done: Membangun mini reactive store berbasis JavaScript Proxy murni dan menjelaskan trade-off kapan sistem membutuhkan framework.
FASE 07 Backend Protokol Jaringan, Evolusi HTTP/3 & Arsitektur API
Terencana
Protokol Transport & Kontrak API
Evolusi HTTP/1.1 (HOL blocking) -> HTTP/2 (Multiplexing, HPACK) -> HTTP/3 QUIC (UDP 0-RTT, seamless migration). Real-time web (Server-Sent Events vs WebSockets). REST Richardson Maturity Model vs GraphQL (Schema AST, DataLoader solving N+1) vs gRPC Protocol Buffers streaming.
✅ Definition of Done: Pembuatan SSE ticker stream real-time dan kompilasi Protocol Buffers dengan pengujian efisiensi payload binary 5x-10x lebih hemat dari JSON.
FASE 08 Backend Autentikasi Modern, Otorisasi & Pertahanan Keamanan API (OWASP)
Terencana
Keamanan API Skala Industri
Stateful Session (Redis) vs Stateless JWT dengan Refresh Token Rotation. OAuth 2.0 PKCE untuk SPA/Mobile. Mitigasi OWASP Top 10 API Security: BOLA/IDOR (Row-Level Authorization), Rate Limiting (Token Bucket & Sliding Window), dan konfigurasi CORS & SameSite Cookies.
⚠️ Common Pitfall: Menyimpan JWT di localStorage browser yang sangat rentan dicuri via XSS.
✅ Definition of Done: Middleware autentikasi aman berbasis HTTP-only cookies, token rotation, dan proteksi brute-force Redis.
FASE 09 Arsitektur Arsitektur Sistem Skala Besar (Monorepo, Modular Monolith, Clean Arch & DDD)
Terencana
Pola Arsitektur Sistem
Monorepo vs Polyrepo (Turborepo, Nx, Bazel). Monolith vs Modular Monolith (in-memory strict boundaries) vs Microservices (Strangler Fig pattern). Clean Architecture & Hexagonal (Dependency Inversion, Ports & Adapters). Domain-Driven Design (Bounded Context, Aggregates, Transactional Outbox Pattern).
✅ Definition of Done: Unit testing use case bisnis 100% terisolasi tanpa database nyata via Mock Repository, dan implementasi Transactional Outbox.
FASE 10 DevOps & Git Linux Kernel Primitives, Kontainerisasi Docker, CI/CD & Git Internals
Terencana
Kernel, Kontainer & Git DAG
Linux Namespaces (PID, NET, MNT) & cgroups v2 resource throttle. OverlayFS layered storage. Docker multi-stage builds (1GB -> 20MB). Docker Compose multi-service. CI/CD pipeline zero-downtime deployment (Rolling/Blue-Green). Git Content-Addressable Storage (Blob, Tree, Commit, Tag), Directed Acyclic Graph (DAG), dan perintah plumbing vs porcelain.
✅ Definition of Done: Multi-service stack via docker-compose.yml dengan healthchecks, pipeline GitHub Actions otomatis, dan pembuatan commit Git murni via perintah plumbing.
